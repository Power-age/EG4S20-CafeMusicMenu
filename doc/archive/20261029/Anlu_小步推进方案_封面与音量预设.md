# 小步推进方案：封面页（480×360）+ 掩膜重排 + 封面禁放大 + 音量预设

## 1. 背景与目标

赛题扩展要求第③条要求"支持不同分辨率图片的读取与缩放显示，以适应 HDMI 输出分辨率"。目前卡上四页都是 1280×960，"小于 640×480 的图放大显示"这一半无法现场演示。

**本次目标**：

1. 页面结构改为 **封面（480×360）+ 三页菜单（1280×960）**；
2. **封面页禁用 2× 局部放大**（该页不是双卡版式，放大无意义）；
3. 封面页不叠加商品文字（掩膜置空）；
4. **新增音量预设开关**：一个拨码在"静音 0 / 满档 15"之间快速切换，日常静音、演示前一拨即到最佳，按键仍可覆盖。

**已取消：每页独立显示几何**（2026/10/28 用户决定）

- 理由：封面 480×360 与菜单 1280×960 都是 **4:3**，`bmp_read.v` 对两者的计算结果都是 640×480、偏移 (0,0)，**显示几何本来就相同，不会串框**；
- 每页几何只对非同比例素材（16:9、竖版）才有意义，而视频演示阶段只用自备 4:3 素材；
- 该项作为**已知边界**记录在案，不实现。

**不在本次范围**：输出分辨率（保持 640×480）、缩放算法（仍为最近邻；大图流式下采样、小图行缓冲上采样）、菜单页版式。

## 2. 现状事实（代码已核）

| 位置 | 事实 |
|---|---|
| `SD/bmp_read.v` | 两条缩放通路都已实现，**无需改动** |
| `SD/bmp_read.v` 大图通路 | 按比例算 `fit_calc_size`，居中黑边：`offset = (目标 − 缩放后尺寸) >> 1` |
| `SD/bmp_read.v` 小图通路（`ST_UP_*`） | 累加器以 `active_width/height = 640/480` 为基准，**拉伸铺满**；4:3 源图即等比放大 1.333 倍 |
| `SD/bmp_read.v:189` | `source_fits_target = (width ≤ 640) && (height ≤ 480)`，决定走上采样还是下采样 |
| `SD/sd_card_bmp.v:754-757` | 装载完成时覆盖唯一的 `display_active_*` 全局几何（本方案不改） |
| `top_tf_hdmi_audio.v:827` | `zoom_key_r = k2_long_v && (sw_key_mode == 1'b1) && !menu_panel_vis`，**无页面门控** |
| `top_tf_hdmi_audio.v:274,638` | `swd_meta/swd_sync` 是 SW2（`sw_con1`）的双触发器同步链，**除赋值外无任何消费端** |
| `pin.adc` | SW1=C8(`sw_con0`)、SW2=C7(`sw_con1`)、SW3=C6(`sw_key_mode`)、SW4=C5(`sw_transition`) |

结论：RTL 需要两处改动——封面页禁放大、SW2 音量预设；其余靠素材与掩膜解决。

## 3. 改动步骤

### 3.1 封面页禁放大（`top_tf_hdmi_audio.v`）

1. `zoom_key_r` 增加页面条件：`&& (e2_disp_buf_sync != 2'd0)`（bank 0 = 封面）；
2. 切页到 bank 0 时强制 `zoom_sel <= 2'd0`，避免在菜单页放大后切到封面仍保留放大态；
3. 放大窗口地址计算不涉页判断，无需改动。

### 3.1b 音量预设开关（SW2，方案 A）

**需求**：平时静音，演示前拨一下即到最佳音量；按键调节仍可覆盖。

**现状事实**：四个拨码中，SW1/SW4 是频谱强调两位、SW3 是切图/切歌模式、**SW2 只做了同步、从未被消费**——方向早已改为"跟随最近一次手动翻页"（`next_dir_lat` 由按键更新），SW2 实际是空置开关。音量寄存器在 `menu_controller` 内（0~15），上电默认 0（静音）。

**设定**：

| 项 | 值 |
|---|---|
| 开关 | **SW2**：上拨（OFF=1）→ 音量 **0**；下拨（ON=0）→ 音量 **15** |
| 生效时机 | **仅在开关翻转的边沿**写入一次，之后按键调节正常覆盖 |
| 上电行为 | 不跟开关位置走，仍默认 0（避免"开关停在下档、上电即出声"） |
| 菜单编辑中 | 开关优先级更高（翻转即覆盖），与"预设"语义一致 |

**实现**：

1. 复用顶层已有的 `swd_meta/swd_sync` 同步链（视频域），把 `swd_sync` 作为新端口 `vol_preset_sw` 接进 `menu_controller`；
2. `menu_controller` 内对 `vol_preset_sw` 打一拍做边沿检测，翻转时 `level <= vol_preset_sw ? 4'd0 : 4'd15`；
3. 复位保持 `level <= 0`（现有默认值不变）。

**代价**：约 10 个触发器 + 一个比较器；不涉及时钟、复位、音频通路，时序风险可忽略。

**文档同步**：`工程交互使用说明文档.md` 把"SW2 = 切图方向"改为"SW2 = 音量预设（上拨 0 / 下拨 15）"，并说明切图方向跟随最近一次翻页。

### 3.2 文字掩膜重排（素材侧，不改 RTL）

新页序：第 1 页封面（无文字）、第 2~4 页沿用原第 1~3 页的两块文字。掩膜 ROM 的 8 个块索引整体后移两格，前两块置零：

| 新块 | 内容 |
|---|---|
| block 0 / 1（第 1 页左右） | **全零** |
| block 2 / 3 | 原 `TXT11` / `TXT12` |
| block 4 / 5 | 原 `TXT21` / `TXT22` |
| block 6 / 7 | 原 `TXT31` / `TXT32` |

做法（实际采用，比原计划更稳）：**不重新解码 BIN，直接在既有 MIF 上按块搬运**。
部署的 `mask_overlay.v` 是 "small" 变体（窗口 200×80、ROM 4096×32bit、每块 512 字、8 块 = `{页号, 左右}`），
而 `make_mask_rom_1bit.py` 生成的是 8192 深的另一套布局，直接重跑会对不上。
因此用 `sim/remap_mask_rom_cover.py` 读旧 MIF → 新块 0/1 置零 → 新块 2..7 = 旧块 0..5 → 写回，并自检逐字一致。
旧文件已备份到 `sim/backups/txt_all_before_cover.mif`。原第 4 页（冰美式/蓝莓麦芬）的两块丢弃。

## 4. 验收方式

**构建门禁**：黑盒 0、无 `PHY-9013`、无 `RUN-8102/PHY-8023`、`.bit` 晚于构建开始时间、`video ≥ 0`、`ext_mem ≥ −0.8`；种子行 `set phyWildParams {place seed N}` 必须仍在 `phy_1/settings.cfg` 里。

**上板清单**：

1. 封面页：480×360 被放大铺满、不变形、无黑边；`PAGE 1/4`、右上歌名倒计时、底部频谱均在；
2. 封面页长按 KEY3 / KEY4：**无反应**；
3. 菜单页：1280×960 缩小铺满，商品文字两侧滑入；
4. 菜单页长按 KEY3 / KEY4：2× 双线性放大正常；
5. **SW2 上拨**：音量立即变 0（静音，频谱归零）；**SW2 下拨**：音量立即变 15；随后按键调音量正常、不被开关覆盖；
6. 上电（开关停在下档）仍为静音 0；
7. 封面 ↔ 菜单页来回切换 3 次：画面正常、文字不串页；
8. 翻页、菜单 7 项、TONE、切歌、±10s 快进快退：与之前一致。

**判错线索**：封面页仍可放大 → 门控条件；文字出现在封面或错页 → 掩膜块顺序；SW2 拨动无反应 → 边沿检测或端口未接；整体花屏 → `ext_mem` 时序。

## 5. 回退与风险

- **回退点**：当前交付 MD5 `49371EEC0EBE2EAC6C28F8B955805E14`（`ext_mem +0.101`）；
- **RTL 风险低**：两处改动都是"加条件/加边沿检测"，不碰时钟、复位、帧缓存、缩放算法、音频通路；
- **素材依赖**：封面必须 4:3，否则小图通路会拉伸变形。

## 6. 任务过程记录

**2026-10-28 20:44 首次构建（seed 5）**：`7E27A5B9…`，`video +12.590` / `ext_mem +0.145` / **`sd −2.222`** / slices 96.06%。

**判据修正（用户 2026-10-28）**：评价时序**只看最差的那条链路**，不能用"两个域变好"去掩盖一个域变差。此前把它表述为"略好"是错的。

**按"最大化最差域裕量"重扫种子**（同一网表、清 DB 强制全量布局，评分 = min(sd, video, ext)）：

| seed | sd_card | video | ext_mem | 最差域 |
|---|---|---|---|---|
| 5（首版） | −2.222 | +12.590 | +0.145 | −2.222 |
| 13 | **−1.345** | +11.390 | −0.359 | **−1.345** |
| 7 | −2.082 | +10.890 | −2.201 | −2.201 |
| 17 | −3.618 | +5.042 | −0.984 | −3.618 |
| 11 | −2.268 | +9.994 | −0.021 | −2.268 |

结论：`sd_card` 是全工程的瓶颈，且对布局极度敏感（同一网表 −1.1 ~ −4.4）。扫种子能把它从 −2.2 压到 −1.14（seed 3），但**代价是 `ext_mem` 从 +0.145 掉到 −0.789**（正好贴门禁 −0.8 红线）。

**最终决策（用户 2026-10-28）：画面优先**——保留 **seed 5**（`ext_mem +0.145` 为正、画面命门域最稳），接受 `sd_card −2.222`。理由：`ext_mem` 是 125MHz 帧缓存域，历史上 −1.95 曾出现横纹；`sd_card` 的负裕量只影响读卡速率，实测 −2.5 仍正常工作。

**交付固件**：`7E27A5B9…`（seed 5）。各候选种子 bit 存于 `sim/backups/seed_sweep_v2/seed{3,13,17,19,23}.bit`，需要时可随时替换。

**工具坑补充**：`phy_1` 的时序报告在完整流程里叫 `HDMI1.4b_Transmitter_v1.0_pr.timing`（9 段汇总，前 3 段依次为 sd_card / video / ext_mem），`final_timing.rpt` 并非每次生成；用 Python `subprocess` 捕获输出跑 TD 会假失败，改用 PowerShell 直接调用 `> $null` 才稳定。
