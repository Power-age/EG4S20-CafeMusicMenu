# Anlu 小步推进方案：滚动字幕（数字标牌场景）

> 2026-10-24 制定。前置决策：作品场景由"客厅音乐相框"改为**离线数字海报屏**（赛题 1.1 列出的五类场景之一）。滚动字幕在标牌场景是标准部件，不再是"干扰照片"的多余元素。

## 1. 背景与目标

**单一目标**：把画面中下部的字幕由"固定季节标题（SPRING/SUMMER/AUTUMN/WINTER）"改为**随图片切换的滚动播报**——每张海报配一句话，6 字符窗口逐字符前进、循环播放；面板打开时整块清空（沿用现有机制）。

**本次不做**：
- 不改字幕窗口几何（仍为 x 272~362、y 400~414）和深色底条（x 232~402）；
- 不改频谱、状态栏、设置面板的任何逻辑；
- 不显示中文（5×7 手绘字库只覆盖 ASCII 大写/数字/符号，做 CJK 点阵不在 8 天窗口内）；
- 不做"浮现-停留-退场"式动画（那需要加宽窗口 + 改 overlay 读地址，列入后续备选）。

**验收判据**：上板后每切一张图，字幕从该图那句话的开头逐字符滚动；文字完整可读、循环不跳字；打开设置面板时字幕区彻底清空；右上状态栏仍每秒正常刷新。

**两条由此推出的硬约束**：

1. **滚动必须突发式**。`sub_busy` 只要持续拉高，状态栏就永远拿不到写口（`sb_req_ready` 需要 `!sub_busy`）。所以每步只写 6 个字符（6×7=42 次写）就释放 busy，再等 0.25 s。
2. **不需要改 overlay**。窗口与读地址都保持现状，滚动靠"换内容"实现而不是"移窗口"。

## 3. 改动步骤

### 3.1 文本载体：BRAM 小 ROM，不用 LUT 查表

拟滚动的文本约 4 条 × ≤60 字符。若用 `case` 常量实现，128~256 项的 7 位查表在 LUT4 上约 100~250 LUT，在当前 96.57% 下不可接受。

改为在 `subtitle_render.v` 内例化一块 `EG_LOGIC_BRAM`（**256 × 7 bit，`INIT_FILE` 指向新文件 `ticker_text.mif`**）：
- 地址 `{img_idx[1:0], pos[5:0]}` ⇒ 每张图独占 64 个字符槽；
- 不新增 `.v` 文件 ⇒ 不需要改 `list.f` / 两个 `.prj`（避开该项目踩过三次的坑）；
- LUT 增量约为 0，BRAM 用掉 1 块（现有 40/64）。

MIF 由脚本生成（沿用 `spec_cos.mif` 的格式：`WIDTH=7; DEPTH=256; DATA_RADIX=HEX;`），内容为 4 条英文大写文案 + 空格补齐，脚本放在 `sim/spec_analysis/` 同级的 `src/user_source/hdl_source/python/` 下便于复现。

### 3.1a 补 6 个标点字形（建议做，风险低）

现有字库只有 `0-9 : A-Z` 与空格有字形，文案里连 `-` `.` `,` `/` `!` `?` 都打不出来，做"展签"会别扭。做法：在 `font5x7_data.mif` 与 `font5x7_data.mem` 里为 6 个 ASCII 码（45/46/44/47/33/63）各画 8 行 5×7 点阵。
- 纯数据文件改动，不新增 `.v`、不改工程文件列表；
- 两份文件必须同步改（`.mif` 给综合、`.mem` 给 ModelSim）；
- 面积零增量（ROM 深度不变）。

### 3.2 相位与循环

- `tick_pos`（6 位）在每个突发结束后 +1，模 64 回绕；
- 可见窗口固定读 `pos+0 … pos+5`（模 64），实现"6 字符窗口在 64 字符槽上滑动"；
- 槽内文案后补空格，形成文字之间的间隔，避免两句首尾相接。

### 3.3 突发写与节拍

状态机加一个"等待"态：`idle → 写 6 字符（复用现有 pos 0..5 流程）→ busy 拉低 → 计时 0.25 s → tick_pos+1 → idle`。
- 单次突发 42 次写 ≈ 42×81 ≈ 3.4k 周期 ≈ 135 µs，占 0.25 s 的 0.05% ⇒ 状态栏/菜单照样能抢到写口；
- 默认 1 字符/0.25 s（约 24 字符≈6 s 滚完一轮），可调。

### 3.4 触发与清空

- `img_changed`：`tick_pos` 归零 + 立即重绘（现有 `drawn` 逻辑天然触发）；
- `!vis`（面板打开）：沿用现有 6 次 `req_fill` 清空（清的是 buffer 列 48~95，与窗口一致，无需改动）；
- `buf_ready`（`osd_clr_done`）：上电清屏完成后才开始，保持现状。

## 4. 验收方式

**功能（ModelSim，tb-first）**

新建 `sim/tb_subtitle_ticker.v`：
1. 连续跑 3 个突发，检查窗口 6 字符 = `tick_text[img][pos..pos+5]`（逐字符比对）；
2. `tick_pos` 到 63 后正确回绕，槽尾空格不产生花字符；
3. 切图（img_idx 变化）后 `tick_pos` 归零、字符换成新图那句话；
4. 面板打开（`vis=0`）时连发 6 次 fill，且之后 `busy` 保持 0；
5. 地址范围检查：`rd_x` 始终落在 48~93、`rd_y` 落在 60~66。

回归：
- `tb_osd_buffer_overlay`（307200 像素比对）——确认窗口/底条/状态栏像素未变；
- `tb_status_bar_render`——确认状态栏逻辑未受影响。

**时序/面积（TD）**

- `syn_1` 先看 `gate.qor` 的 slices；**综合后若 slices 估算 > 97.5% 就退回简化方案**（见 §5）；
- 通过后再 `phy_1`；核对 bit 时间戳、`PHY-9009`/`PHY-8023`/`RUN-8102`、`route.qor`；
- 视频域 `video_clk` SWNS 必须 ≥ 0（当前 +8.024ns）。

**上板（最终判据）**

- 切图后字幕从该图文案开头逐字符滚动，可读、不跳字、循环正常；
- 面板打开字幕消失、关闭后重新开始；
- 右上状态栏每秒仍在刷新（验证仲裁没被饿死）；
- 频谱、音乐、切图、转场、亮度对比度、音量全无回归。

## 5. 回退点与风险

| 项 | 内容 |
|---|---|
| 回退基线 | 固件 `FF9EB7AA`（slices 96.57%），源码快照 `sim/backups/spec_c1_20261024/`；本次只改 `subtitle_render.v` + 新增一个 `.mif`，回退即恢复该文件 |
| 面积风险（主要） | 96.57% 已近临界（历史：98.29% 时 Setup 崩到 −6044ps）。BRAM 方案 LUT 增量应 <40；**若综合后 slices > 97.5%，立即退回**：①文案缩短到 4×32 字符；②去掉逐字符滚动、改为每 2 s 整句切换（省掉连续突发）。 |
| 仲裁风险 | 若状态栏因字幕突发过密而刷新滞后，把步进从 0.25 s 放宽到 0.4 s，或把突发拆成两段（每段 3 字符）。 |
| 文本风险 | 字库只有 `0-9 : A-Z` 与空格，小写与多数标点为空白字形；文案一律大写，或先做 §3.1a 补标点 |
| 内容风险 | 文案是演示内容的一部分，最终由用户确认 |
