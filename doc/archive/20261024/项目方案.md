## 2. 设计美学规范摘要

所有界面元素必须遵循以下设计约束（完整规范见视觉呈现方案 V3 第 3 章）：

- **配色**：面板 `#1A1D23`(alpha75%)、文字 `#F0EDE8` 米白、次色 `#A8A49C`、强调色 `#E8A838` 暖琥珀、波形 `#5BC0BE` 青绿
- **字体**：8×8 位图圆润字体，字间距 1px，行高 12px，菜单项行高 20px
- **圆角**：面板 8px、选中色块 4px、百分比条 2px
- **动效**：所有过渡 ≥100ms，ease-in-out 缓动；选中色块平滑滑动（非瞬间跳转）
- **状态栏**：渐变背景（顶部透明→底部不透明），5 秒无操作淡出至 alpha30%
- **整体**：非交互状态 OSD 总亮度 ≤ 画面 15%，文字对比度 ≥7:1

## 5. 任务清单


### 第一批：音频波形可视化（唯一未做加分项⑤）

> **音频部分现状**（本批起点）：
> - **已完成**：WAV 流式播放（旧方案任务 16，`wav_stream_player.v`，48kHz 16bit 单声道 PCM）、音量调节（4 位 16 档，`audio_volume_gain.v`）、转场音频淡入淡出
> - **已有但简单**：4 位电平条（`audio_level_bar`，基于峰值检测 + 过零率计算 4 位电平值，送到 HDMI TX 核的 `.I_audio_level` 端口显示）——这不是赛题意义上的"波形/频谱"
> - **本批目标**：从 4 位电平条升级为 640 点填充式波形（赛题加分项⑤"音频可视化表现"），波形数据从 WAV 播放器 PCM 输出端（音量增益后、I2S 发送前）截取，确保波形与听到的声音同步
> - **PCM 数据来源**：WAV 播放器输出 16bit 有符号小端 PCM（48kHz 单声道），经 `audio_volume_gain` 音量增益后，在送入 I2S 发送之前截取一路作为波形数据源

#### 任务 1（V2-01）：波形数据通路（PCM 包络/降采样/对数压缩/BRAM 缓存）

**目标**：
- 从音量增益后、送入 HDMI 发射核前的 signed 24bit 左右声道最终 PCM 计算包络，收集为 640 点，并通过近似对数压缩提升低音量可见度
- 波形数据缓存到 BRAM（640×8bit = 5120bit = 640byte，可容纳于 1 个 BRAM9K），供 V2-02 渲染模块读取
- 左右声道各自求饱和绝对值后取最大值，确保任一声道有声音时波形可见

**修改思路**：
1. 新建 `waveform_data.v` 模块：
   - 输入：signed 24bit 左右 PCM、`video_clk`、与 HDMI 音频发送一致的 `audio_valid`
   - 输出：波形缓存写口（地址 0~639、数据 8bit、写使能）、块完成脉冲（640 点收集完）
   - 逻辑：
     a. 包络：左右声道分别求饱和绝对值，负满幅单独饱和处理，再取两路最大值
     b. 降采样：每 `SAMPLES_PER_POINT` 个有效样本取窗口峰值；当前默认值为 1，因此 48kHz 下 640 点约覆盖 13.33ms，约 75 块/秒；60fps 帧同步留给 V2-03
     c. 对数压缩：使用最高有效位和 3bit 尾数形成单调近似对数编码，再用固定移位加法映射至 8bit；不使用乘法、除法或 DSP
     d. 写入 BRAM：地址计数器 0~639 循环，每形成 1 点写 1 个地址
2. 波形缓存：新建 `waveform_ram.v`（物理 1024×8bit、逻辑使用 0~639；写口接 waveform_data，读口供 V2-02 waveform_render 使用；同步读延迟一拍并输出 `rd_valid`）
3. 数据从顶层现有 `vol_audio_l`、`vol_audio_r` 与 `audio_valid` 旁路截取，不修改 WAV 播放器和 HDMI 音频路径
4. V2-01 只建立数据通路，不接视频渲染、不产生用户可见变化

**涉及文件**：
- 新增 `waveform_data.v`
- 新增 `waveform_ram.v`
- `top_tf_hdmi_audio.v`：在音量增益后旁路连接最终 PCM，例化 waveform_data 与 waveform_ram
- WAV 播放器模块不改

**调试方案**：
1. ModelSim 自检：静音、正负对称、正负满幅、左右声道最大值、单调压缩、窗口峰值、地址 639→0 回绕和完成脉冲
2. ModelSim 自检：waveform_ram 地址 0/1/639 的写读与一拍同步读时序
3. 完整顶层编译与 elaboration，确认新增模块无隐式线网、位宽/符号错误、多驱动或锁存
4. 用户在 TD GUI 中 Add Source 后执行综合检查；若缓存因读口尚无消费者而被裁剪，记录为预期，待 V2-02 接入读口后确认 BRAM 资源

**验证标准**：
- 静音映射为 0，正负满幅映射为 255，全输入范围映射单调且低幅非零可见
- 左右声道交换结果一致，等幅反相不会抵消
- 640 点地址严格循环，块完成脉冲与地址 639 的写入对齐
- 缓存同步读时序和 `rd_valid` 对齐正确
- 模块测试、顶层编译及用户 TD source/综合检查通过
- V2-01 可按模块级结果独立完成；屏幕波形与音乐同步的可视上板验收归 V2-02，E10 在此之前仍是当前上板稳定点

#### 任务 2（V2-02）：波形渲染（填充式/青绿色渐变/峰值保持线）

**目标**：
- 将 V2-01 的单路左右最大包络显示为全宽 640px、高 24px 的填充式波形
- 波形固定在 `x=0~639、y=408~431`：位于右侧电平条下方 4px、现有滚动字幕正上方，不移动或遮挡既有 OSD
- 波形采用四级青绿色渐变（#5BC0BE → #3A8A88）与约 80% alpha，背景画面仍可见
- 每列显示 1px 白色峰值保持线，以 0.5px/帧缓慢衰减

**修改思路**：
1. 新建 `waveform_render.v`：
   - 在 `vout_data_base` 与 `video_osd_overlay` 之间插入，使波形参与既有亮度/对比度、reveal 和 fade，并保持字幕与其他 OSD 在波形上层
   - 分时仲裁 waveform RAM 读口：活动波形区按像素 x 读取，垂直消隐期为峰值后台更新读取
   - waveform RAM 同步读一拍；RGB、x/y、vs/de 同步延迟一拍后与返回数据合成，OSD 和 AXIS 同时改接延迟后的 vs/de
   - 高度使用移位加法实现精确 `floor(amplitude×24/255)`，不使用通用乘除或 DSP
   - 四级颜色每 6px 一档；alpha 使用 `13/16` 波形色与 `3/16` 背景色近似 80%
2. 新建 `waveform_peak_ram.v`：
   - 物理 1024×6bit、逻辑使用 0~639，必须推断为独立 BRAM9K
   - 峰值采用 Q5.1：当前高度左移一位，每帧减 1 个 Q 单位即 0.5px/帧
   - 复位后串行清零 0~639；垂直消隐期逐列读取 waveform/旧峰值并写回 `max(current, old-1)`；活动区只读峰值显示
   - 禁止用 640 项寄存器/LUT 数组替代；若任一 RAM 未落 BRAM，综合阶段暂停
3. 顶层连接 waveform RAM、peak RAM 与渲染器；原音频、SDRAM刷新、转场状态机和坐标生成保持原时序
4. V2-02 允许单份 waveform RAM 实时边写边读产生轻微局部跳变；双缓冲、60fps 稳定提交和帧间平滑留给 V2-03

**涉及文件**：
- 新增 `waveform_render.v`
- 新增 `waveform_peak_ram.v`
- `top_tf_hdmi_audio.v`：连接两块 RAM，插入波形渲染管线，统一延迟 OSD/AXIS 的 vs/de
- `waveform_ram.v`：接口原则上不改，只在综合中确认真实读消费者使其落入 BRAM
- `工程交互使用说明文档.md`：上板通过后同步波形区域、样式、峰值与演示说明

**调试方案**：
1. ModelSim 验证 peak RAM、串行清零、每帧 0~639 扫描、尾部排空、高度映射、Q5.1 衰减、四级渐变、alpha 与一拍视频对齐
2. 回归 V2-01 三个测试台、WAV 真实时钟比和数字音量测试
3. TD 综合必须确认 waveform RAM 与 peak RAM 各占 1 个 BRAM9K、DSP 不增加；若未满足则停止，不进入布局布线
4. 上板验证波形位置、幅值响应、颜色、alpha、峰值衰减、转场一致性和既有功能回归

**验证标准**：
- 波形仅位于 `x=0~639、y=408~431`，不覆盖滚动字幕或右侧电平条
- WAV、测试音和音量档变化均能驱动波形；静音无填充，最大幅值接近 24px
- 四级青绿色由上到下正确，填充半透明，白色峰值线不透明并以 0.5px/帧衰减
- 无固定一列偏移、行首残留、断行或 HDMI 失锁；reveal/fade 与波形一致
- waveform RAM 与 peak RAM 各落入 1 个 BRAM9K，DSP 增量为 0
- 既有图片、切图、轮播、方向、亮度/对比度、WAV、音量和拔卡恢复无回归
- 轻微实时局部跳变可记录并留 V2-03；明显闪烁、峰值异常或固定错位不能通过

#### 任务 3（V2-03）：显式双BRAM + 帧同步平滑 + 48px居中对称波形

**目标**：
- 用两个显式BRAM9K组成front/back波形缓存，消除V2-02的Logic DRAM/LUT膨胀与边写边显示
- 按实际视频帧窗口把音频样本稳定映射为640列，在消隐期完成横向与时间平滑后原子提交
- 波形改为全宽48px居中上下对称样式，位于`y=380~427`，与字幕间保留4px
- 删除白色峰值线和右侧旧音频电平条，降低视觉杂讯

**修改思路**：
1. 存储：两个物理1024×8bit显式`EG_LOGIC_BRAM`，front只读显示、back采集/滤波写；只在消隐期且地址639最终写回后翻转front
2. 动态采样：使用上一窗口实际接受样本数作为下一窗口DDA分母，将约802~807个有效样本按窗口峰值映射到640列；每轮重置相位，尾列不足时补齐，不跨帧累积漂移
3. 空间滤波：边界复制的`[1,2,1]/4`三点滤波；时间滤波：`old×5/16 + new×11/16`，全部使用移位加法，首帧直接使用空间滤波结果
4. 视觉：全宽`x=0~639`、区域`y=380~427`，围绕`y=404`上下各24px镜像；非零低幅至少1px；填充色`#5BC0BE`、alpha13/16；中心线`#A8A49C`、alpha6/16
5. 删除V2-02峰值RAM/白线通路；删除`video_osd_overlay`右侧电平条及顶层旧4bit电平统计链路，保留最终PCM到HDMI和波形采样器
6. 分三阶段推进：R先验证双BRAM资源与原子提交，S再加动态采样/滤波，V最后改视觉并删除旧电平条；每阶段独立ModelSim和TD综合门槛

**涉及文件**：
- `waveform_ram.v`：重构为双显式BRAM与front/back端口
- `waveform_data.v`：改为按视频帧窗口的动态DDA采样与back写入
- `waveform_render.v`：原子front读取、滤波控制与48px对称渲染
- `top_tf_hdmi_audio.v`：双bank控制、移除peak与旧电平统计、视频接线
- `video_osd_overlay.v`：删除右侧旧音频电平条
- `waveform_peak_ram.v`：从活跃TD工程移除
- `工程交互使用说明文档.md`：最终上板通过后同步新波形与删除电平条

**调试方案**：
1. 阶段R综合确认两个waveform bank各占1个BRAM9K、BRAM总数31→33、peak RAM不参与综合、LUT明显低于V2-02
2. ModelSim覆盖800~807样本窗口、长期帧映射无漂移、空间/时间滤波黄金值、超时不翻bank和地址639排空
3. 最终TD检查DSP保持13、Slice低于90%、hold无违例且waveform路径不成为关键负裕量
4. 上板验证48px对称波形、中心线、幅度/音量响应、无半帧乱跳，并回归全部既有功能

**验证标准**：
- 两个waveform bank各落入1个BRAM9K，BRAM总数33；不再出现waveform Logic DRAM大规模LUT展开
- 活动区整帧只读同一front，只有完整back处理完成才在消隐期原子翻转
- 实际约59.52Hz帧率下无周期性横向漂移；横向与帧间过渡自然，无明显滞后
- 波形仅位于`x=0~639、y=380~427`，上下对称；旧电平条和白色峰值线消失，字幕不被挤压
- 小信号至少1px，大音量接近上下各24px但不长期饱和
- DSP不增加，最终hold WNS≥0且无hold违例；waveform/video_clk路径不成为新增关键路径
- 连续运行30分钟无闪烁、错列、断行或HDMI失锁，既有图片、转场、WAV、音量、OSD和拔卡恢复无回归

#### 任务 4（V2-04）：固定编号裸PCM多曲目播放

**目标**：
- 扫描FAT32根目录中的`TRACK01.RAW`~`TRACK16.RAW`，按编号槽建立曲目列表
- 格式固定为48kHz、16bit signed、小端、单声道、无文件头裸PCM
- 音量模式下key1/key2短按松手调音量−/＋，长按分别上一首/下一首；切图模式不变
- 最后一首与第一首回绕；最后一个真实样本播放完后自动下一首
- 当前曲目名和索引输出，为V2-08状态栏预留，本任务不显示

### 第二批：OSD Buffer 架构重构


> 本批是整个视觉升级的基础。当前 `video_osd_overlay` 实时计算 OSD 消耗约 1700 LUT，改用 Buffer 架构后净释放约 1200 LUT，同时界面表现力大幅增强。参考 MiSTer FPGA OSD 架构。

#### 任务 5：字体 ROM + OSD Buffer 存储基础设施

**目标**：
- 新建 8×8 位图字体 ROM（ASCII 32-127，共 96 字符，768 字节），1 个 BRAM9K
- 新建 OSD 像素 Buffer（256×16 像素，2bit/像素：00=透明/01=面板/10=文字/11=高亮），1 个 BRAM9K
- Buffer 坐标空间：x∈[0,255]，y∈[0,15]，对应屏幕上 256×128 像素区域（每 Buffer 像素=屏幕 8×8 像素块）

**修改思路**：
1. 新建 `font_rom.v`：8×8 位图字体，选择圆润字形（参考 Fixedsys 风格），输入字符 ASCII（7bit）+ 行号（3bit），输出 8bit 像素行
2. 新建 `osd_buffer.v`：双口 BRAM，写口（渲染状态机写入）+ 读口（视频管线读取），2bit 数据宽度，地址 = y[3:0]×256 + x[7:0]
3. 字体数据用 `$readmemh` 从 `.mem` 文件初始化，或直接在 Verilog 中用 case 硬编码（96 字符×8 行=768 个 8bit 值）
4. 顶层例化 font_rom 和 osd_buffer，先不接渲染和叠加逻辑（任务 6/7 再接）

**涉及文件**：
- 新增 `font_rom.v`
- 新增 `osd_buffer.v`
- 新增 `font_data.mem`（字体点阵数据，或硬编码在 font_rom.v 内）
- `top_tf_hdmi_audio.v`：例化两个新模块

**调试方案**：
1. 编译通过，确认 BRAM 占用增加 2 块（从 31→33）
2. ModelSim 仿真：向 osd_buffer 写入测试数据，读口验证读出正确
3. font_rom 仿真：输入字符 'A'（0x41），验证 8 行输出符合 'A' 的点阵

**验证标准**：
- font_rom 输出字符点阵正确
- osd_buffer 双口读写正常（写后可读，读写不冲突）
- BRAM 占用 +2，LUT 占用接近零（纯存储）

#### 任务 6：消隐期渲染状态机 + 行级脏标记

**目标**：
- 在 VS 消隐期间（约 1.2ms）运行渲染状态机，将菜单/状态栏内容渲染到 OSD Buffer
- 行级脏标记：只有被修改的行才重绘，减少运算量
- 渲染能力：在指定 (x,y) 位置写一个 8×8 字符（从 font_rom 取字形，展开为 8 行×8 列像素写入 Buffer）

**修改思路**：
1. 新建 `osd_renderer.v` 模块：
   - 输入：渲染请求（字符 ASCII、目标 x[7:0]、目标 y[3:0]、像素类型 2bit）、font_rom 读口
   - 输出：osd_buffer 写口（地址、数据、写使能）、busy 信号、done 脉冲
   - 状态机：IDLE → READ_FONT（等 font_rom 输出）→ WRITE_ROW0..7（逐行写入 8 个像素）→ DONE
2. 行级脏标记：16bit 寄存器 `dirty_row`，每 bit 对应 Buffer 一行；设置界面选中项变化时只标记受影响的 2 行（旧选中行+新选中行）
3. 渲染调度：VS 脉冲到来时，遍历 dirty_row，对每个脏行调用字符渲染（一行可能含多个字符，需逐个渲染）
4. 注意：渲染必须在消隐期间完成，避免与视频管线读 Buffer 冲突（双口 BRAM 天然支持，但同一地址同时读写可能有问题，用消隐期保证安全）

**涉及文件**：
- 新增 `osd_renderer.v`
- `top_tf_hdmi_audio.v`：例化 osd_renderer，连接 font_rom 和 osd_buffer

**调试方案**：
1. ModelSim 仿真：发送渲染请求（字符 'A'，位置 x=10,y=2），验证 osd_buffer 对应地址写入正确像素
2. 仿真连续渲染多个字符，验证不会重叠或丢失
3. 上板：先写一个测试图案（如全屏写"文字"类型像素），任务 7 叠加后验证可见

**验证标准**：
- 单个字符渲染在 8 个时钟周期内完成（8 行×1 周期/行）
- 连续渲染不丢字符
- 脏行标记正确，只重绘被修改的行
- 消隐期间能完成至少一整行（32 个字符）的渲染

#### 任务 7：视频管线 4 类像素 alpha 混合叠加

**目标**：
- 视频管线 active 区域按坐标判断是否在 OSD 区域内，从 osd_buffer 读 2bit 像素类型，执行 alpha 混合
- 4 类像素：00=透明（输出原视频）、01=面板（原视频与 #1A1D23 按 alpha75% 混合）、10=文字（输出 #F0EDE8 不透明）、11=高亮（原视频与 #E8A838 按 alpha35% 混合）
- 替代当前 `video_osd_overlay` 模块（释放约 1700 LUT）

**修改思路**：
1. 新建 `osd_overlay_buffer.v` 模块：
   - 输入：视频像素（RGB 24bit）、像素坐标（x,y）、osd_buffer 读口数据
   - 输出：叠加后视频像素（RGB 24bit）
   - 逻辑：判断 (x,y) 是否在 OSD 面板区域内（可配置的矩形区域，如 x∈[192,447], y∈[176,303]，对应 256×128 像素居中偏左）→ 计算 Buffer 地址 → 读 2bit 像素类型 → 按类型混合
2. alpha 混合公式：`out = fg×alpha + bg×(1-alpha)`，用移位+加法近似（alpha=75% → fg×3/4 + bg×1/4；alpha=35% → fg×1/3 + bg×2/3 近似）
3. 顶层：用 `osd_overlay_buffer.v` 替换 `video_osd_overlay.v`，旧模块的 OSD 内容渲染改由任务 6 的渲染状态机负责
4. 注意时序：osd_buffer 读口有 1 周期延迟，需要把视频像素打一拍对齐

**涉及文件**：
- 新增 `osd_overlay_buffer.v`
- `top_tf_hdmi_audio.v`：替换 OSD 叠加模块，连接 osd_buffer 读口
- `video_osd_overlay.v`：保留文件但从顶层移除（或直接删除）

**调试方案**：
1. 上板：用任务 6 的测试图案（全屏写"面板"类型像素），验证屏幕上出现半透明暖灰色覆盖层
2. 测试"文字"类型像素，验证出现米白色不透明块
3. 测试"高亮"类型像素，验证出现半透明琥珀色块
4. 对比替换前后 LUT 占用，确认释放约 1200~1500 LUT

**验证标准**：
- 4 类像素混合效果正确（透明/面板/文字/高亮）
-  alpha 混合无明显色偏（用灰阶图测试）
- 视频显示正常，无闪烁/花屏
- LUT 占用净下降 ≥1000（OSD Buffer 架构释放的资源）

#### 任务 9：状态栏渐变背景 + 5 秒自动淡出 + 波形融合布局

**目标**：
- 状态栏背景从顶部透明渐变到底部 #1A1D23 alpha80%（不是纯色条，与照片自然融合）
- 5 秒无操作后，状态栏整体淡出至 alpha30%（仍可辨识但不抢眼）；任何按键/拨码操作时立即恢复全亮
- 波形与状态栏融合布局：波形嵌入状态栏上方区域，渐变背景连续，两者视觉上为一个整体
- 可通过设置界面"信息显示"项完全关闭状态栏（后续任务 13 接入）

**修改思路**：
1. 渐变背景：在 `osd_overlay_buffer.v` 中，对状态栏区域（y 在底部 28px 范围内）的"面板"类型像素，alpha 值按 y 坐标线性变化（顶部 y=0 → alpha=0%，底部 y=27 → alpha=80%）。用简单的移位实现：`alpha = y[4:0] × 80% / 28`（近似为 y×3，饱和在 80）
2. 自动淡出：维护 `idle_counter`（秒计数），5 秒无操作后设置 `status_dim=1`；`status_dim=1` 时状态栏所有像素的 alpha 乘以 30%（即面板 alpha 从 80%→24%，文字从 100%→30%）
3. 操作检测：任何按键（key1/2/3）或拨码变化时，清零 `idle_counter`，`status_dim=0`
4. 完全关闭：增加 `status_enable` 信号，=0 时状态栏区域全部输出透明像素（任务 12 从设置界面接入）
5. 波形融合布局：波形区域（任务 1~3 已实现）与状态栏区域共用底部空间，波形渲染在状态栏渐变背景之上。布局：波形 y∈[452,475]（24px），状态栏渐变背景覆盖 y∈[452,479]（28px），波形叠加在渐变背景上（波形 alpha80%）。叠加顺序：先状态栏渐变背景，再波形，最后文字。需调整 waveform_render.v 区域坐标和顶层叠加顺序

**涉及文件**：
- `osd_overlay_buffer.v`：增加渐变 alpha 计算、淡出逻辑、使能信号
- `waveform_render.v`：调整波形区域坐标，与状态栏融合
- `top_tf_hdmi_audio.v`：连接按键/拨码操作检测到 idle_counter；调整波形和状态栏叠加顺序

**调试方案**：
1. 上板：验证状态栏背景是渐变的（顶部几乎透明，底部较深），不是生硬的纯色条
2. 验证波形和状态栏在视觉上是一个整体（渐变背景连续，无生硬分界线）
3. 静置 5 秒，验证状态栏淡出至约 30% 亮度（波形也一起淡出）
4. 按任意键，验证状态栏立即恢复全亮
5. 反复操作，验证淡出/恢复无闪烁

**验证标准**：
- 状态栏背景渐变自然，与照片融合无生硬边界
- 波形与状态栏融合为一体，无生硬边界
- 5 秒无操作后淡出至 ~30%（波形和文字一起淡出），操作后立即恢复
- 淡出/恢复过渡平滑（建议 500ms 渐变，非瞬间跳变）
- 文字在淡出状态下仍可辨识

**面板尺寸与 OSD Buffer（2026/10/20 读码核定）**

现状约束（实测代码）：

| 项 | 现值 |
|---|---|
| `osd_buffer` | 256 列 × **16 行**，2bit/像素，共 4096 像素 |
| `font_rom` | **8×8** 点阵（128 字符 × 8 行 × 8bit） |
| 屏幕映射 | `osd_buffer_overlay` 用 `rd_x=rel_x[8:1]` / `rd_y=rel_y[4:1]` → **1 buffer 像素 = 2×2 屏幕像素** |
| 现有显示能力 | 1 字 = 8×8 buffer 像素 = **16×16 屏幕像素**；全 buffer 仅够 **32 字符 × 2 行文字** |

结论：**7 项菜单 + 标题共 8 行文字需 64 个 buffer 行，现有 16 行差 4 倍，必须扩容。**

**决定：`osd_buffer` 扩到 256×80**（16384 × 2bit = 32 Kbit，占 4 块 BRAM9K，BRAM9K 由 36 增至 **40/64**，约 63%）。扩容后文字容量为 **32 字符 × 10 行**，满足 8 行菜单并留 2 行余量。

配套做法：

- 面板**半透明底、圆角、边框**按状态栏横幅的既有做法，由 `osd_buffer_overlay` 的几何直接绘制，**不占 buffer**；仅文字与选中色块走 buffer。
- 面板尺寸按 256px 宽（居中）× 约 136~160px 高（标题 + 7 项 16px 行高 + 上下边距）实现；V2-10 原文"256×180"作废。
- V2-10 原文以"buffer 像素=屏幕 8×8 块"推算的 `y∈[2,13]` 等行号作废，一律按 2×2 映射重新计算。

**本规格影响的既有设计**

- 原任务 12 的"key3 调出、key1/key2 移动、sw_con0 边沿增减、长按退出"全部作废。
- 原任务 13 的"参数复位值：音量=70%"作废，音量沿用 E15 的**上电默认 0**。
- 原任务 10 的面板位置由"居中偏左"改为**居中**，行数按 7 行菜单调整。
- 原任务 10 的面板高度 180px 与 buffer 行号推算作废，改为 **256px 宽 × 约 136~160px 高**，且**`osd_buffer` 须先扩到 256×80**（+4 BRAM9K）。

#### 任务 15：溶解转场（LFSR 伪随机像素混合）

**目标**：
- 新增溶解转场：旧图像素随机逐个变为新图像素，类似溶解效果
- 时长 600ms，ease-in-out 缓动
- 用 LFSR（线性反馈移位寄存器）生成伪随机数，不占 BRAM/DSP

**修改思路**：
1. 在转场模块中增加 DISSOLVE 模式：
   - 32 位 LFSR 生成伪随机数（多项式 x^32+x^22+x^2+x+1，或更简单的 16 位 LFSR）
   - 每个像素用坐标 (x,y) 作为种子，生成伪随机阈值 `rand_val`
   - `rand_val < t ? 新图 : 旧图`（t 从 0→255，逐渐有更多像素变为新图）
   - 为了避免每帧随机图案完全不同（闪烁），用固定的像素种子（x,y 组合），这样每个像素的阈值是固定的，t 增加时逐个像素翻转，不会闪烁
2. LFSR 实现：16 位 LFSR，种子 = {x[7:0], y[7:0]}（或 x[9:0]+y[8:0] 的哈希），迭代若干次后取低 8 位作为阈值。迭代次数越多随机性越好，但消耗逻辑越多。简化：迭代 8 次（组合逻辑），或迭代 1 次（用 x,y 直接作为伪随机数，效果接近噪点溶解）
3. 转场进度：600ms，每帧 +7（60fps×0.6s=36 帧，255/36≈7.1）
4. 注意：溶解转场在 t=50% 时画面是一半旧图一半新图的随机噪点，可能看起来比较"花"，这是溶解效果的正常表现

**涉及文件**：
- 转场模块：增加 DISSOLVE 模式和 LFSR 逻辑
- `top_tf_hdmi_audio.v`：转场模式选择

**调试方案**：

2. 验证转场时长约 600ms

4. 验证转场完成后完全显示新图

**验证标准**：

### 第六批：视频缩放升级（高风险，最后做）


#### 任务 17：双线性插值缩放

**目标**：
- 图片缩放从最近邻升级为双线性插值，边缘平滑无锯齿
- 支持放大和缩小
- 需 2 行缓存（4 BRAM9K）+ 8~12 DSP（资源消耗大，最后做）

**修改思路**：
1. 参考教程第十三讲 `bilinear_8q8.v`
2. 双线性插值原理：对目标像素，找到源图中最近的 4 个像素（2×2），按距离加权平均：`out = (1-dx)(1-dy)P00 + dx(1-dy)P10 + (1-dx)dyP01 + dxdyP11`
3. 实现：
   - 2 行缓存：存储当前行和上一行的源图像素（每行 1024 像素 × 24bit = 24Kbit ≈ 3 个 BRAM9K，两行 = 6 个？或用 1024×16bit 简化）
   - 分数坐标：目标像素对应的源图坐标是分数，整数部分取像素，小数部分作为权重
   - 乘法器：4 个像素 × 3 通道（RGB）= 12 个乘法，每个乘法 8bit×8bit=16bit，需要 8~12 个 DSP
4. 资源风险：DSP 当前 13/29（44.8%），双线性需 8~12 个，做完后 21~25/29（72%~86%），接近上限。如果 DSP 不够，简化为双线性的近似（只用水平方向插值，垂直方向最近邻，减少一半乘法器）
5. 教程参考：`完赛系列/第十三讲/bilinear_8q8.v`，先读教程理解接口再移植

**涉及文件**：
- 新增 `bilinear_scaler.v`（或移植教程 `bilinear_8q8.v`）
- `bmp_read.v` 或视频管线：替换最近邻缩放为双线性
- `top_tf_hdmi_audio.v`：例化双线性缩放模块
- TD 工程：可能需要生成 IP（如 BRAM 行缓存）

**调试方案**：

4. 验证帧率正常（双线性比最近邻慢，但应保持 60fps）

**验证标准**：

#### 任务 24：参数持久化到 SPI Flash

**目标**：
- 亮度/对比度/音量/转场方式/轮播周期等参数断电不丢失
- 上电时从 SPI Flash 读取参数，参数变化时写入 Flash
- 参考旧方案任务 25，教程 `完赛系列/第五讲/player_config_persistence.v`

**修改思路**：
1. 参考教程 `player_config_persistence.v`、`config_flash_journal.v`、`w25q64_record_store.v`
2. SPI Flash 引脚：CS=P8、SDO=N8、SDI=P7、SCLK=M9、WP=P9、HOLD=R9
3. 实现：
   - 上电时：发送读命令，从 Flash 指定地址读取参数（7 个参数约 16 字节）
   - 参数变化时：等待 2 秒无操作后，发送写命令写入 Flash（避免频繁写入）
   - 使用 wear leveling（损耗均衡）：参数在 Flash 的多个扇区循环写入，避免单个扇区反复擦写
4. 简化方案：只持久化音量/亮度/对比度/转场方式 4 个参数，轮播周期和信息显示用默认值
5. 注意：SPI Flash 写操作需要先擦除扇区（4KB），擦除时间约 45ms~200ms，期间不能读

**涉及文件**：
- 新增 `config_persistence.v`（或移植教程模块）
- 新增 `spi_flash_driver.v`（SPI 读写驱动）
- `top_tf_hdmi_audio.v`：例化持久化模块，连接参数寄存器
- `pin.adc`：补充 SPI Flash 引脚约束

**调试方案**：
1. 上板：调亮度到 80，断电再上电，验证亮度保持 80
2. 调音量到 50，断电再上电，验证音量保持 50
3. 验证参数变化后约 2 秒写入 Flash（不是每次拨动都写）
4. 验证上电读取参数不影响首图显示速度（读取在后台进行）

**验证标准**：
- 参数断电保存，上电恢复
- 写入不频繁（变化后 2 秒延迟）
- 上电读取不影响首图显示
- SPI Flash 读写正常，无错误
