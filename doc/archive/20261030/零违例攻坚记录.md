### hold 违例的收尾（setup 全绿之后）

首版零违例 bit（`E4BBA8EE`）setup 全绿，但 **HWNS 仍有 8 个端点 −12~−20ps**。原因：TD 流程里 `fix_hold` 只在 `arr_filter == "on"` 时执行，而本工程是 `arr_filter false`，**hold 修复从未跑过**。

处理：把 `DefaultFlow.tcl` 复制为 `sim/DefaultFlow_hold.tcl`，在 `route` 之后**无条件插入 `fix_hold`** 再 bitgen。修复后 hold 全部转正（最小 +0.024ns），setup 不受影响。

注：手工 `import_db` + `fix_hold` 的写法会让 TD **崩溃（coredump）**，必须走“流程内插入”的方式。

## 关键结论（避免重复踩坑）

- **改 `sys_pll.v` / `sys_pll.ipc` 源文件对时序无效**：TD 综合用的是 `syn_1/syn_ip/` 的 IP 数据库；连续三次构建时序数字**逐位相同**即为证；
- **必须在 TD GUI 里双击 `sys_pll.ipc` → 改 C0 → OK/Generate** 才生效；`Tools` 菜单里没有 IP Manager，入口是文件树里的 `.ipc`；
- GUI 生成会**丢掉未勾选的输出**（本例丢了 `PLL lock`），而顶层 `rst_all` 依赖它 → 需手工把原语 `extlock` 引出为 `lock_out`；
- `place phys_opt` / `place enforce_phys_opt` 对该设计**无增益**（布局逐位相同）；
- 降频代价：SPI 25 → 18.75MHz，图片加载 4.5s → 约 6s。

## 实验 1：删除死代码 `subtitle_render`（✔ 结构有效）

- 依据：该模块自 2026/10/25 起 `vis` 钉为 `1'b0`（旧点阵字幕停用），仍例化、仍占面积。删除实例、7 个输出常量化为 0。
- 结果（seed 5）：**`sd_card` −2.222 → −0.639**（好 1.58ns）；`ext_mem` +0.145 → +0.010（仍 0 违例）；slices 96.06% → 96.55%。

## 实验 2：同网表扫种子（✘ 未转正）

清 DB 全量布局、只跑 phy：最优 **seed 23 → −0.578**；其余 seed 5 −0.639 / 3 −0.784 / 13 −1.148 / 19 −1.670 / 7 −3.147 / 17 −8.368。**波动区间 −0.58 ~ −8.37**，靠抽布局不足以转正。

## 实验 3：簇号 → LBA 两级流水（✔ 该路径已不是最差）

原 `fat32_volume_scanner.v:533-536` 把「减 2 → 变移位 → 加 `data_start_lba`」串成一条链、驱动两个 32 位寄存器。改为两级：

```
root_clu_off_q  <= (fat_nextc - 2) << sectors_per_cluster_shift;   // 第一级
root_lba_next_q <= data_start_lba + root_clu_off_q;                // 第二级
root_lba <= root_lba_next_q;  sector_lba <= root_lba_next_q;
```

安全性：FAT 条目 4 字节在 sector 流早期到齐，距 `sector_done` 数百拍；`data_start_lba`/`sectors_per_cluster_shift` 在该状态内不变。
效果：该路径**退出了最差列表**（新最差变为 `bmp_read` 的 `active_height → scale_out_x`），说明 `sd_card` 域是一群"中等长度"路径，单点优化有限。

## 实验 4：改 PLL 分频（✘ 完全无效）

分别改 `hdl_source/IP/sys_pll.v` 的 `.CLKC0_DIV(10→13)`、以及 `sys_pll.ipc` 的 `clock_division_factor`/`clock_frequency`，重新综合+布线后**时序报告里的时钟周期仍是 10.000ns**（`video 25MHz`、`ext_mem 125MHz` 也未变），两种改法都无效。
→ **TD 的 PLL 频率不取自这两个文件**（推测固化在工程/IP 数据库里），只能在 **TD GUI 的 IP Manager 重新生成 IP** 才会生效。

## 实验 5：开物理优化（✘ 无变化）

`set phyWildParams {place seed 5 place phys_opt on place enforce_phys_opt on}` —— 日志确认 `set_param` 被接受，但布局结果与不开**逐位相同**（同 seed 确定性），说明这两个开关对该设计无增益。
