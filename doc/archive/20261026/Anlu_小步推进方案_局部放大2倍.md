# 小步推进方案：局部放大 2×（显示读通路行缓冲）

## 1. 背景与目标

对应 `项目方案.md` §7 任务 2（也是作品形态里唯一还标"未做"的功能）。

**目标（单一）**：长按 KEY3（约 0.6s）进入 / 退出 **2× 放大**，画面显示当前页照片的中心 320×240 区域铺满 640×480；信息条、设置面板、卡内文字、频谱**保持原尺寸**。

**本次不做**：
- 不做平滑/双线性插值（最近邻 2×，与现有缩放口径一致）；
- 不改 `bmp_read` 的写侧缩放、不动 SDRAM 四个 bank 的常驻结构；
- 不做放大时的平移/漫游（中心固定）；
- 不改转场、频谱、音频。

## 2. 当前代码事实（已核）

| 位置 | 现状 |
|---|---|
| `SD/video_timing_data.v` | 产生 `hs/vs/de`（像素时序），`vs` 边沿发一帧的 `read_req` |
| `SD/frame_read_write.v` | `read_addr_0~3`（bank 基址）与 `read_len` 都是**输入端口**；`read_clk` 侧 `read_en` 每拍从 FIFO 取 1 像素 |
| `SD/frame_fifo_read.v` | `read_addr_index` / `read_len` 在 `read_req` 时**锁存**（同步两拍），支持任意基址+任意长度 |
| `SD/video_delay.v` | 纯固定延迟：`read_en = de_d[18]`，`de_d[19]` 采样 `read_data`，输出 `de_r/vs_r/hs_r = *_d[20]` |
| `top` 第 1110~1150 行 | `frame_read_write_m0`：`.read_addr_n(BANKn)`、`.read_len(FRAME_PIXELS=307200)`、`.read_en(video_read_en)` |
| `top` 第 36~40 行 | `FRAME_PIXELS=307200`，`BANKn = n*FRAME_PIXELS`（每 bank 连续 640×480） |
| `top` 第 838~853 行 | `video_delay_m0` 输出 `hs/vs/de/vout_data_raw`；`vout_data_base = display_image_area ? vout_data_raw : 0` |
| `top` 第 1222~1230 行 | `key_longshort` 已用于 key1/key2（`LONG_CYCLES=15_000_000` = 0.6s，`REPEAT_ENABLE=0`）；key3 目前只有 `key_press_debounce` 的 `press_pulse`（按下即触发） |

**关键结论**：读侧是"线性突发 + FIFO + 固定 20 拍延迟"，**不能按输出像素改读地址**；但读窗口（基址/长度）可以改。放大必须在 FIFO 与 `video_delay` 之间加一层行缓冲。

## 3. 改动步骤

### 步骤 1：`video_zoom.v`（新增，核心）

接口：`clk, rst, zoom_en, de, vs, fifo_data[31:0]` → `z_data[23:0]`（喂 `video_delay.read_data`）、`z_pop`（喂 FIFO 的 `re`）。
内部另有一份 20 拍 `de` 延迟链复刻 `video_delay` 的节拍，用它产生 `de18/de19`。

行为（`zoom_en=1` 时）：
- **采集**：在每个偶数显示行（`y[0]==0`），按 1 像素/时钟把该源行的 640 个像素拉出 FIFO（`z_pop = de18`）；只保留列 160~479（320 个），写入当前采集行的 bank；
- **显示**：输出像素 `x` 取 bank 中 `(x>>1)`，即水平 2×（最近邻）；
- **垂直 2×**：每两行显示同一个源行（`r = y>>1`），行 bank 交替：显示行 `2r/2r+1` 读 bank `r&1`，同时在 `2r` 采集 `r+1` 到另一个 bank；
- **预采集**：`y=0` 这一行用来采集第 0 行并输出黑，`y=1` 起显示，由此产生**顶部 1 行黑**的已知现象（480 行里 1 行，后续可另行优化）；
- **`zoom_en=0` 时**：`z_pop=0`、`z_data=0`，整条通路被顶层旁路，`video_delay` 原样工作。

存储：1 块 `EG_LOGIC_BRAM`（32bit × 1024，A 端采集写、B 端按地址读、`REGMODE_B=NOREG` 组合读），两个 320×24 行 bank 放在同一块里（偏移 0 与 512）。

### 步骤 2：顶层接入（精确编辑，四处）

1. `read_addr_n` 改为 `zoom_en ? BANKn + 17'd76800 : BANKn`（76800 = 120×640，取行 120~359）；
2. `read_len` 改为 `zoom_en ? 153600 : FRAME_PIXELS`（240×640）；
3. 新增 `video_zoom u_video_zoom`：`.fifo_data(video_read_data)`、`.z_pop(z_pop)`；
4. `video_delay` 的 `.read_data` 改接 `zoom_en ? z_data : video_read_data`；FIFO 的 `re`（`video_read_en`）改接 `zoom_en ? z_pop : video_read_en`。

`zoom_en` 由长按 KEY3 的 `long_repeat` 触发，**在 `vs` 边沿才更新生效**，避免一帧内改窗口。

### 步骤 3：KEY3 改成长短按

- 用 `key_longshort #(.CLOCK_MHZ(25), .LONG_CYCLES(15_000_000), .REPEAT_ENABLE(0))` 替换 key3 现在的 `key_press_debounce`；
- `short_pulse`（松手）→ 原 `key3_trig` 面板通路；`long_repeat` → 放大开关；
- **行为变化**：面板由"按下触发"变为"松手触发"（双击关闭、15 秒超时逻辑不变）；面板打开时长按忽略。

### 步骤 4：三处工程登记

`HDMI1.4b_Transmitter_v1.0.al` 与 `syn_1` / `phy_1` 两份 `.prj` 追加 `video_zoom.v`。

### 步骤 5：仿真先行（不烧板）

- 新增 `sim/tb_video_zoom.v`：造 240×640 的合成源流（每像素 = `{行号,列号}` 编码），跑两种模式；
- 断言：`zoom_en=1` 时输出 640×480；第 `2r+1/2r+2` 行内容相同；每行内 `x` 与 `x^1` 像素相同；输出像素对应源列 `160+(x>>1)`、源行 `120+(y>>1)`；
- 另把输出帧写成 PPM 并转 PNG，肉眼核对裁剪位置与重复方式（不烧板）。

### 步骤 6：构建 + 用户上板

`sim/loop.ps1 -Seed 17` 三门禁通过后烧录，交用户按第 4 节清单核对。

## 4. 验收方式

**我这边（仿真）**：`tb_video_zoom` 全通过 + 渲染图与预期一致；`vlog` 无错；构建三门禁通过（黑盒 0 / 无 PHY-9013 / bit 本次新产出），并记录 slices 与分域时序。

**用户上板核对清单**：
1. 长按 KEY3 约 0.6 秒 → 画面变成**中心 2× 特写**（咖啡杯/面包等细节明显变大），全屏铺满、无黑边；
2. 再长按一次 → 恢复原 1:1 画面；
3. 放大状态下：左上 `PAGE n/4`、右上歌名/倒计时、卡内文字、频谱**都是原尺寸**（不跟着放大）；
4. 短按 KEY3 → 设置面板正常打开（松手时打开）、双击关闭仍正常；
5. 放大状态下按 KEY2/KEY4 翻页 → 仍保持放大，显示新页的同一区域；
6. 已知现象：放大画面**顶部可能有 1 行黑线**（行缓冲预采集造成的），如不能接受再改；
7. 失败判据：花屏/错行/撕裂/画面上下颠倒/放大区域偏出画面 → 立即回退。

## 5. 回退点与风险

- **回退点**：E19.3，MD5 `841B079F16107120E417569CBA153719`（`sim/backups/bit_E19.3a_841B079F.bit` 有备份）。
- **回退步骤**：`zoom_en` 直接接 `1'b0`（保留新文件但不实例化亦可），KEY3 恢复 `key_press_debounce`，重新构建；或直接烧回备份 bit。
- **风险**：

| 风险 | 影响 | 缓解 |
|---|---|---|
| 行缓冲采集/显示节拍错 | 错行、上下颠倒、撕裂 | tb 逐像素断言 + PPM 渲染核对，未通过不烧板 |
| 采集抢不到 FIFO 数据 | 首行花块 | 采集只落在 `de` 高电平内，读窗口长度与采集量严格相等（153600） |
| 一帧内改窗口 | 单帧错位 | `zoom_en` 只在 `vs` 边沿更新 |
| 面积/时序 | slices 上涨、违例 | 只 +1 BRAM 与约 +120 LUT；构建后记录时序，超阈值就换种子 |
| KEY3 语义变化 | 面板手感变化、双击异常 | 上板清单第 4 条专门核对 |
