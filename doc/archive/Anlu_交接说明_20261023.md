## 3. 未修缺陷（用户 2026/10/23 08:00 反馈）

### 缺陷 1：开面板时仍触发旧的 KEY3 功能（亮度递增）

**现象**：按 KEY3 开面板，**有概率**（实际是每次）同时把亮度 +1。

**已定位原因（代码级确定）**

`top_tf_hdmi_audio.v`：

```verilog
else if (key3_trig && !menu_active) begin      // ← 亮度/对比度递增
```

`menu_active` 由 `menu_controller` 在**下一个时钟沿**才拉高。按下那一拍 `key3_trig=1` 而 `menu_active` 仍为 0，于是**每次开面板都顺带 +1 亮度**。面板挡住画面时亮度变化不明显，所以用户感觉是"概率性"。

**建议修法**

- 方案 A：控制器额外输出 `open_press`（开面板那一拍的脉冲），亮度逻辑改为 `key3_trig && !menu_active && !open_press`
- 方案 B：让 `menu_active` 在 CLOSED→BROWSE 的**同一拍组合逻辑**即拉高（把 `active` 改成 `(state != S_CLOSED) || (sel_short && state == S_CLOSED)`）

### 缺陷 2：面板打开后按 KEY2，高亮条不移动

**现象**：面板打开状态下按 KEY2，高亮没有上下移动。

**排查起点（未验证）**

1. 用 ModelSim 抓波形：`u_menu_controller/sel_row`、`u_menu_controller/redraw`、`u_menu_renderer/row`、`/idx`、`/running`、`/drawn`。
2. 重点确认 `redraw` 单拍脉冲到来时渲染器是否真的重画（渲染器在 `!running` 才响应，代码里有强制复位分支，但可能与 `sel_row` 采样存在一拍错位）。
3. 另需确认 `k1_short_v`（KEY2 的短按脉冲）在面板打开时是否仍正常产生（`key_longshort` 例化在 `top` 约 L1070 附近，输入是原始 `key1`）。

**已知易错点**：`menu_controller` 的 BROWSE 分支里，`sel_short` 被用于清除 `suppress_single`，与"移动高亮"共用同一 case 链，改动时注意别误伤。

## 5. 构建流程（必须遵守）

1. 进 `syn_1` 目录，先删所有 `*error*` 文件
2. 执行（**正斜杠必须**）：
   `D:/TD5.6.2/bin/td_commands_prompt.exe "D:/TD5.6.2/doc/scripts/DefaultFlow.tcl"`
3. **成功判定**：日志无 `ERROR`，且残留错误标记的时间戳属于本次（历史遗留的 `.opt_gate.error.f` 会造成误判）
4. 进 `phy_1` 目录执行同一命令
5. **路由失败仍返回 exit 0**：必须检查日志无 `PHY-8023` / `RUN-8102`，且 bitstream 时间戳晚于构建开始
6. 放置种子：`phy_1/settings.cfg` = `settings.cfg.bak` 的内容 + `set phyWildParams {place seed N}`
   - 当前 seed 3；实测同网表 seed 1/5 更差
7. **新增源文件必须同时加进 `syn_1` 和 `phy_1` 两个 `.prj`**，否则报 `is a black box`（此坑已踩三次）

**仿真**：ModelSim，`sim/work_e15` 下 `vlog -work work -f list.f`（`list.f` 已含全部源文件）；
两条厂商加密文件的报错（`sdr_init_ref.enc.v` / `sdr_wrrd.enc.v`）是**已知无害**。
