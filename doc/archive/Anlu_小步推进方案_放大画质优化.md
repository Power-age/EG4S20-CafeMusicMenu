# Anlu 小步推进方案：小图放大画质优化（过渡行 / 双线性）

> **来源**：2026/10/20 用户确认 PIC3 放大"轻微错行"实为 1.6 倍最近邻的固有行重复不均（`tb_bmp_read` 断言 `map_err = 0` 证明取行逻辑正确），提出希望改善观感。
> **当前稳定点**：E15 + 一期约束 + 二期 A/B/D/C1（已上板功能正常；Setup 364 端点 / −1.731，slices 92.46%，BRAM 36/64，DSP 13/29）

---

## 1. 背景与目标

### 现状与问题本质

1.6 倍放大时，源行被复制次数按 `0,0,1,1,2,3,3,4,5,5,...` 分布（约 60% 两次、40% 一次），输出行**成对硬重复**，视觉上呈现行距时疏时密。

这不是缺陷，是最近邻算法的固有特性。

### 本次目标

让输出行的行间过渡变平滑，消除"硬重复"的观感。

### 关键约束：现有架构一次只能看到一行

`bmp_read.v` 的升采样是**单行缓冲 + 拉取-发射**：

| 状态 | 作用 |
|---|---|
| `ST_UP_READ` | 从 SD 流式读一行到 `up_row_mem`（1024×24，1 块 BRAM） |
| `ST_UP_SCALE` / `ST_UP_EMIT` | 以 `up_row_mem[up_emit_src_x]` 逐点发射 |
| `ST_UP_REPEAT` | 推进输出行，必要时推进源行 |
| `ST_UP_FETCH` | 拉下一行 |

**做任何纵向过渡都必须同时持有相邻两行**，因此必须先扩成双行缓冲。这是本任务的主要工作量，也是主要风险（改 FSM）。

## 2. 方案分档与代价（必须先选）

### 方案 A：过渡行（2 行缓冲 + 50/50 平均）

- 新增第二块行缓冲 `up_row_mem2`（1024×24 → **+1 BRAM9K**，36 → 37）；
- FSM 改为：拉第 k 行进 A → 拉第 k+1 行进 B → 对落在两行"之间"的输出行输出 `(A+B)>>1`，落在源行上的仍输出原值 → 交换角色继续；
- 混合只需 **1 个 24 位加法 + 1 次右移**，**不用 DSP、不用乘法**。

| 项 | 估计 |
|---|---|
| 面积增量 | +1 BRAM，约 +100~200 LUT |
| 时序风险 | 中（FSM 改动 + 面积上升） |
| 观感改善 | 消除硬重复，明显平滑；但会略微变柔（50/50 无权重） |
| 风险点 | 双缓冲交替的边界处理容易出错，需 tb 黄金校验和 |

### 方案 B：完整双线性（2×2 加权）

- 同样需要双行缓冲，另需水平方向取相邻两列；
- 每个输出像素做 4 点加权：`(1-fy)(1-fx)·A + (1-fy)fx·B + fy(1-fx)·C + fy·fx·D`；
- 权重来自 `up_scale_y_acc / active_height` 与 `up_scale_x_acc / active_width` 的小数部分；
- 需要 **至少 3 个乘法器**（RGB 各一，8×8 或 12×12）→ **DSP 13 → 16 左右**，外加较多 LUT。

| 项 | 估计 |
|---|---|
| 面积增量 | +1 BRAM，**+3~6 DSP**，+300~600 LUT |
| 时序风险 | **高**（slices 已 92.46%，很可能把违例推高） |
| 观感改善 | 接近标准双线性，最佳 |

### 我的判断

**先做方案 A**。理由：不改乘法器、面积增量小，能直接解决用户看到的"硬重复"；做完上板看效果，再决定是否值得为方案 B 承担时序回退风险。

**重要提醒**：当前 slices 已 92.46%、还有 364 个违例端点。任何加法都会增加面积并可能恶化时序——**这不是纯功能开发，是一次功能与时序的交换**。方案 A 做完必须重跑 TD 核对；若 WNS 明显变差，需要权衡是否接受。

## 3. 实施步骤（按方案 A）

### 步骤 1：先扩 tb 能力（TB 先行）

现有 `tb_bmp_read`（源 20×30 → 输出 32×48，比例 1.6）已验证取行映射正确，可直接复用。需要补充：

- 记录完整输出像素序列（不只校验和），用于改动前后**逐点比对**；
- 断言：输出行数、每行像素数、以及"落在源行上的输出行必须与原值完全一致"。

### 步骤 2：双行缓冲结构改造

- 新增 `up_row_mem2`（第二块 1024×24 BRAM，与现有同参数）；
- 用 `row_bank` 标志决定当前发射读哪块、写哪块；
- FSM 增加"预取下一行"阶段：先填 A，再填 B，之后每推进一个源行只需填一块并交换。

### 步骤 3：过渡行混合

- 纵向小数权重 `fy_num = up_scale_y_acc`（范围 0 ~ active_height-1），`fy_den = active_height`；
- 简化策略：**当 ` fy_num` 落在中间 1/2 区间时输出 `(A+B)>>1`，否则输出最近行原值**；
- 混合作用于 24 位像素（R/G/B 各 8 位，分别 (x+y)>>1，避免进位串色）。

## 5. 回退点与风险

**回退点**：当前生效版本（A/B/D/C1，已上板验证，Setup 364 端点 / −1.731）。本任务只改 `bmp_read.v` 一个文件。

| 风险 | 影响 | 缓解 |
|---|---|---|
| 双缓冲交替边界出错 | 隔行错位、图像撕裂 | tb 逐点比对 + 上板看 PIC3 |

### 记录 1：方案建立（2026/10/20）

- 确认"错行"为最近邻固有现象（`map_err = 0` 证明取行正确）。

### 记录 2：改走"横向 2-tap"并实施完成（2026/10/20 23:31）

**为什么改路线**：读 FSM 后发现升采样是 `ST_UP_PREP → ST_UP_READ → SCALE → FETCH → EMIT → REPEAT → 回 PREP`，**每个输出行都会把同一源行从 SD 重新读一遍**，行缓冲里永远只有当前一行。纵向过渡必须先做双缓冲 + 行循环重构（`ST_UP_REPEAT` 不再无条件回 `PREP`），属 FSM 主干改动，风险高于收益。经用户确认改走**横向 2-tap**（相邻源列都已在本行缓冲内，无需额外 BRAM、无需改行循环）。

**实施内容**（`SD/bmp_read.v`）

| 位置 | 改动 |
|---|---|
| L67 后 | 新增状态 `ST_UP_HS = 5'd20` |
| 声明区 | 新增 `reg [23:0] up_pix_a` |
| `up_row_rd_en` | 增加 `|| (state == ST_UP_HS)`，利用原 EMIT 前的空拍做第二次取数 |
| `up_row_rd_addr` | HS 状态取 `up_next_src_x`（`src_x+1`，越界钳到 `src_x`），其余取 `src_x` |
| 新增 wire | `up_next_src_x`、`up_hblend_en`（`W/4 < up_scale_x_acc < 3W/4` 时启用）、`up_pix_mix` |
| 新增 always | `state == ST_UP_HS` 时 `up_pix_a <= up_row_rd_data`（锁存左邻像素） |
| 数据通路 | `ST_UP_EMIT` 的 `bmp_data <= up_hblend_en ? up_pix_mix : up_pix_a` |
| FSM | `ST_UP_FETCH → ST_UP_HS → ST_UP_EMIT`（每像素多 1 拍） |

**过程中修掉的一个真 bug**：`up_pix_mix` 最初写成 `{ (A[23:16]+B[23:16])>>1, ... }`，三个 9 位和拼起来是 **27 位**，赋给 24 位会截断错位，导致行和骤降 18%。改为先取名 8 位和 `up_sum_r/g/b`（各 9 位）再取 `[8:1]` 拼接，行和恢复为合理值。

**仿真验证**（`tb_bmp_read`，源 20×30 → 输出 32×48）

| 项 | 基线 | 横向 2-tap 后 |
|---|---|---|
| `active_w/h` | 32 / 48 | 32 / 48 |
| `wr_pixels` | 1536 | **1536**（不变） |
| `map_rows` / `map_err` | 48 / 0 | **48 / 0** |
| `row 0` 行和 | 213387288 | **216991801**（+1.7%，与"相邻列取均值"理论增量吻合） |
| `sum_data` / `xor_data` | 1692050432 / 184 | 1865065904 / 244 |

按 `acc ∈ {12,16,20}`（共 8 种取值的 3 种）判定，约 **37.5%** 的输出像素参与混合，与行和增量一致。

**TD 结果**

| 指标 | 改动前 | 横向 2-tap 后 | 判定 |
|---|---|---|---|
| Setup WNS | −1731ps | **−1883ps** | 差 152ps（< 500ps 阈值，**不触发回退**） |
| Setup TNS | −231281ps | **−207885ps** | 改善 |
| Setup 违例端点 | 364 | **329** | **减少 35** |
| Hold | −11 / 5 | −11 / 3 | 略好 |
| slices | 92.46% | **92.32%** | 略降 |
| BRAM / DSP | 36 / 13 | **36 / 13** | **未增加** |

**结论**：面积几乎零代价（BRAM、DSP 均未增，slices 反降），违例端点减少，WNS 小幅让步。按约定保留。

**代价**：每像素多 1 拍，升采样行发射从 2 拍/像素变 3 拍/像素；480 行 × 320 像素 → 约 46 万拍 ≈ 4.6ms（100MHz），相对 SD 读图耗时可忽略。

**待上板**：PIC3 放大观感是否明显平滑；PIC1/PIC2/PIC4 无回归；冷上电黑边仍纯黑。

### 记录 3：方向澄清——用户主诉是横向条纹（纵向重复不均），横向 2-tap 未解决（2026/10/20 23:34）

用户澄清："刚才主要的问题就是有**横向的突兀条纹**"，经选项确认指**条纹水平延伸、上下重复不均**，即**纵向过渡问题**。

## 7. 纵向过渡行设计（已规划，未实施——下次会话直接开工）

### 目标

把"新源行的第一份输出行"改为与上一行的 50/50 混合，使行间从硬跳变变为渐变：

```
原序列:  ..., k-1, k-1, k,          k+1, k+1, ...
改后:    ..., k-1, k-1, 混合(k-1,k), k+1, ...
```

### 为什么用"保留上一行"而不是"预取下一行"

- 预取下一行需要提前把 k+1 读进来，行循环要改成两级流水，改动大；
- 保留上一行只需在写入新行时**不覆盖旧行**，`ST_UP_REPEAT` 的流转基本不动。

### 实施要点

| 项 | 内容 |
|---|---|
| 行缓冲 | 新增第二块 `up_row_mem2`（1024×24，**+1 BRAM9K，36 → 37**），用 `row_bank` 选择写哪块、读哪块与 `row_bank^1` |
| 写入 | `ST_UP_READ` 写入 `row_bank` 指向的缓冲；读旧行时用另一块 |
| 新行标志 | `ST_UP_REPEAT` 中 `up_source_y` 自增时置 `is_new_row`，进入 `ST_UP_EMIT` 后清 |
| 取数节拍 | 每像素需 4 次读：当前行 c、当前行 c+1、上一行 c、上一行 c+1 → 每像素 5 拍（现为 3 拍） |
| 混合 | `is_new_row` 且 `row_bank` 的上一行有效时，输出 (当前行 + 上一行) 的 8 位分量均值；否则输出当前行（仍保留横向 2-tap 逻辑） |
| 首行保护 | 第一个源行没有上一行，`prev_valid` 为 0 时退化为纯当前行 |

### 验收方式

`tb_bmp_read`（源 20×30 → 输出 32×48）现有逐行校验和可直接判定：

- 每个源行的**第二份**输出行（如 row 1、3、6）行和必须**不变**；
- 每个源行的**第一份**（如 row 2、5）行和必须等于 `(当前行 + 上一行)/2` 的预期值，TB 可用源图解析式 `B=(x+y)*7, G=y*13, R=x*11` 直接算出；
- `wr_pixels`、`map_rows`、`map_err` 必须不变。

### 风险与回退

- **风险最高的一步**：动行循环与读写银行选择，历史上 C1/C2 两次 FSM 改动都在板上出过问题。必须 TB 全绿再上板。
- **回退点**：横向 2-tap 版本（Setup 329 端点 / −1883ps / slices 92.32%，已上板验证功能正常）。
- 若 TD 后 WNS 恶化超过 0.5ns 或端点增加超过 100，按既定规则回退。

### 记录 4：纵向过渡首次尝试——部分生效但模式错误，已回退（2026/10/20 23:44）

**已实现的部分**（`SD/bmp_read.v`，均已回退）

- 行缓冲 1024 → **2048 深**（最高位当银行号），新增状态 `ST_UP_HP` / `ST_UP_HP2`，每像素取数 2 次变 4 次（当前行 c/c+1、上一行 c/c+1）；
- 新增 `row_bank_wr`（写银行）、`prev_valid`（上一行有效）、`is_new_row`（新源行首份）三个标志；
- 新增锁存 `up_pix_b`（当前行 c+1）、`up_prev_c`（上一行 c），配合 `up_row_rd_data`（上一行 c+1）构成 2×2 取样；
- 混合：先横向（`up_hblend_en`）得到 `up_cur_base` 与 `up_prev_base`，再纵向（`up_vblend_en = is_new_row && prev_valid`）求均值。

**仿真结果（错误模式）**

用 TB 探针打印每行的 `src` 与 `is_new_row`：

```
row 2 : src 1 : new 1   ← 混合生效
row 4 : src 2 : new 1   ← 混合生效
row 5 : src 3 : new 1   ← 标志正确，但未混合
row 6 : src 3 : new 0   ← 标志为 0，却被混合
row 7 : src 4 : new 1   ← 未混合
```

**`is_new_row` 标志完全正确**，但混合只落在第 2、4、6 行，之后全部失效。即"标志对、取数错"——双缓冲的上一行取数在**连续两次源行推进**（第 3 行后进 src2、第 4 行后进 src3）之后就走偏了，怀疑是银行翻转与写覆盖顺序不匹配，或 `up_prev_c`/`up_row_rd_data` 的拍位对齐在多次翻转后错位。

**处理**：已完整回退（状态定义、地址位宽、缓冲深度、锁存、标志、FSM 跳转、混合逻辑全部复原），并用 `tb_bmp_read` 确认回到横向 2-tap 黄金值（`sum_data 1865065904`、`xor_data 244`），**源码与已交付 bitstream（23:31:02 / MD5 D348C941）一致**。

**下次继续的要点**

1. 双缓冲的核心不变量要先写清并逐拍验证：**任意时刻 `row_bank_wr` 指向刚写入的当前行，`row_bank_wr^1` 必须仍是上一行**；连续推进时若两次翻转发生在相邻输出行，中间那次写入会覆盖"上一行"。
2. 更稳的做法可能不是"翻转 + 原地写"，而是**固定三缓冲轮转**或**写指针与读指针分离**，避免"刚写入的银行恰好是下一步要当上一行读的银行"。
3. 调试手段已就绪：TB 可打印每行 `src`、`is_new_row`、行校验和，能直接看出哪一行取值错。
4. 该改动风险高（FSM 主干 + 双缓冲），务必 TB 全绿再上板；回退点就是当前横向 2-tap 版本。
