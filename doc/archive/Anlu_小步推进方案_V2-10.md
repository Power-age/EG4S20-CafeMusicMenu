# Anlu 小步推进方案：V2-10 设置面板视觉渲染

> **来源**：《Anlu_后续整体推进方案》阶段 1，2026/10/23 任务。规格以 `项目方案.md` §4.0 为准。
> **基线**：阶段 0 完成版（`MD5 FE58458E`）。slices 92.06%（9022）、BRAM 40/64、DSP 12/29、Setup WNS −853ps、Hold +3ps/0 违例。

---

## 1. 目标

在画面上渲染一个**居中弹出式设置面板**：

| 项 | 规格 |
|---|---|
| 尺寸 | **256px 宽 × 160px 高** |
| 位置 | 屏幕正中（x 192~447、y 160~319） |
| 背景 | 半透明暖灰 `#1A1D23`，alpha 75% |
| 圆角 | 8px（4 个角各去掉 1 个 buffer 像素） |
| 边框 | 1px 亮边 `#FFFFFF` alpha 8% |
| 标题 | 面板顶部居中，下方 1px 分隔线 |

**本任务只做"静态外观"**：面板始终显示（调试态），显隐控制留给 V2-12。

---

## 2. 必须解决的规格偏离：文字只能用英文

`font_rom` 实测为 **128 字形 × 8×8 点阵，仅 ASCII**（`address = {ascii[6:0], row[2:0]}`，`ascii >= 32` 才有效）。

- 8×8 的中文字形不可辨认，放大到 16×16 屏幕像素也只是把 8×8 马赛克放大，不能读。
- 要做中文标题需 16×16 点阵字库（另建 ROM、另改渲染路径），成本与本阶段不匹配。
- 现有状态栏本来就是英文（`ANLU HDMI` / `SD:` / `AUTO` / `BRI` / `CON`），英文是既有惯例。

**决定：面板文字全部用英文。**

| 位置 | 规划文案 |
|---|---|
| 标题 | `SETTINGS`（8 字符 = 128px，面板内居中） |
| 菜单项（V2-11） | `VOLUME` / `BRIGHT` / `CONTRAST` / `TRANS` / `AUTO` / `PERIOD` / `INFO` |

> 此偏离需用户确认。若必须中文，则需先新增 16×16 中文字库，属独立任务。

---

## 3. 坐标系与换算

- 屏幕 640×480；`osd_buffer` 256 列 × 80 行 × 2bit；**1 buffer 像素 = 2×2 屏幕像素**。
- 面板 256px 宽 → **128 个 buffer 列**（0~127）；160px 高 → **80 个 buffer 行**。
- 但 buffer 只有 80 行，且状态栏占用 72~79 行 → **面板可用 0~63 行（128px）**，面板高度改为 **144px**（上下各留 8px 内边距给标题/边框）。

| 元素 | 屏幕坐标 | buffer 坐标 |
|---|---|---|
| 面板外框 | x 192~447、y 168~311 | x 0~127、y 0~71 |
| 文字区 | x 200~439、y 184~311 | 列 4~123、行 8~71 |
| 标题行 | y 184~199 | 行 8~15 |
| 菜单区（V2-11） | y 200~311 | 行 16~71（7 行 × 8 = 56 行） |

> 面板高度最终取 **144px**（不是 §4.0 的 136~160 折中值），因为缓冲 80 行里 72~79 已被状态栏占用。

## 4. 实现拆分

### 4-1 覆盖层几何（`osd_buffer_overlay.v`）

新增 `panel_vis` 输入（本任务内接常量 1，供调试观察）。绘制层次：

1. **背景**：面板区域内做 `mix75(原图, PANEL_COLOR)`；
2. **圆角**：面板四个角各 1 个 buffer 像素（=2×2 屏幕像素）不绘背景；
3. **边框**：面板最外 1 屏幕像素行/列用 `mix35(原图, BORDER_COLOR)`；
4. **读地址复用**：面板文字区与状态栏文字区共用 `rd_x/rd_y` 端口，按窗口选择（面板 → `(x-192)>>1`, `(y-184)>>1`+8；状态栏 → 原逻辑 72 行起）。

### 4-2 文字请求仲裁

现有 `osd_renderer` 只有一个请求源（`status_bar_render`）。加入面板标题后变成两个源，需一个简单仲裁：

- 优先级：面板请求 > 状态栏请求；
- 仲裁器放在 `top`（约 20 行）：用 `req_ready` 做握手，面板未就绪时状态栏等待。

### 4-3 标题渲染

新增 `menu_renderer.v`：本任务只发 `SETTINGS` 这 8 个字符的请求（字符码、buffer 列 12~19、行 8、类型 `2'b10`）。菜单项在 V2-11 扩展。

### 记录 1：面板几何实现完成（2026/10/21 13:40；待上板看外观）

**实现内容**（`osd_buffer_overlay.v`，另加顶层一个连接）

- 输出选择：横幅区走原有 `blend_rgb`，其余走面板层 `pnl_out`，二者 y 区间不重叠。

**第一版超门禁并已修剪**：初版把"面板文字层"也一起做了（`ptxt_win` 读地址复用、typ 01/11 高亮分支），slices 冲到 **94.05%**、超过 94% 门禁。修剪为"只做几何"（文字留 V2-11）后回到 **93.36%**（seed 3）。修剪内容：删面板文字窗口与读地址复用、删 typ 高亮分支、边框改用 `mix8` 移位而非 `mix_a` 乘法。

**TD 结果（每种子的差异极大）**

| seed | Setup WNS | TNS | 违例端点 | Hold | 路由 |
|---|---|---|---|---|---|
| 3 | −5140 | −449524 | 441 | −60 / 7 | 成功 |
| 1 | −7517 | −323823 | 349 | −20 / 3 | 成功 |
| **5（采用）** | **−3049** | −352506 | 441 | −20 / 4 | 成功 |
| 7 | −3243 | −310536 | 521 | −11 / 5 | 成功 |

**采用 seed 5**：slices 9211（**93.99%**，贴着 94% 门禁）、BRAM 40、DSP 12、线长 1801672，bitstream `MD5 10316149`。

**时序退化的根因（重要）**

最差路径不是 OSD，而是 `sd_card_bmp_m0/bmp_read_m0/width_reg[24] → sel39.mi[0]`：

```
12.891ns，逻辑 6 级（ADDER×4 + MULT18×1 + LUT3），扇出 47
```

即 **`bmp_read` 的等比适配计算链（fit_calc）**——C2 完成时就预判它会是下一个真实瓶颈。它本身就需要 12.9ns，只要布局稍差就会违例（10 亿分之一的运气问题）。面板逻辑只是搅动布局把它暴露出来，**不是面板造成的**。

**结论与下一步**：V2-10 几何功能已就绪，先上板确认外观；时序债单独记，建议下一步先优化 fit_calc 链（对该链打拍或把 `bmp_width * fit_calc_size_clamped` 的乘法改为累加），否则 V2-11~13 继续加逻辑会让时序继续恶化。
