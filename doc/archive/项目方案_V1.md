## 1. 硬件资源

### 按键（4 个，A2 被用作复位，实际可用 3 个）

> key1/key2 的功能由拨码 SW3（C6，sw_key_mode）硬切换：**未拨=切图模式，拨到 ON=音量模式**，两种功能互不误触发。

| 按键 | FPGA引脚 | 开发板手册名称 | 当前工程名称 | 切图模式（SW3 未拨） | 音量模式（SW3 拨 ON） |
|------|---------|--------------|-------------|------|------|
| 复位 | A2 | KEY1 | rst_n | 复位（不受模式影响） | 复位（不受模式影响） |
| key1 | B2 | KEY2 | key1 | 手动下一张 | 音量 −（短按一下一档） |
| key2 | C1 | KEY4 | key2 | 自动播放开关 | 音量 +（短按一下一档） |
| key3 | B1 | KEY3 | key3 | 亮度/对比度调节（SW1 选调谁，不受模式影响） | 同左 |

### 拨码开关（4 个乒乓开关）

| 拨码 | FPGA引脚 | 开发板手册名称 | 当前工程名称 | 用途 |
|------|---------|--------------|-------------|------|
| SW1 | C8 | SW1 | sw_con0 | **选调亮度/对比度**（KEY3 调谁） |
| SW2 | C7 | SW2 | sw_con1 | **sw_dir 方向选择**（下一张/上一张） |
| SW3 | C6 | SW3 | sw_key_mode | **按键模式选择**：未拨=切图模式（key1 下一张/key2 自动播放），拨到 ON=音量模式（key1 音量−/key2 音量+）；原"恢复默认"已取消 |
| SW4 | C5 | SW4 | sw_transition | 转场模式（保留不动） |

### 数码管（8 位共阳极）

- 段选：DIG0~DIG7（对应 a~g+dp）
- 位选：SEL0~SEL7（左起第 1~8 个数码管）
- 和双色 LED 复用，由 SW6 硬件开关切换（拨上=数码管，拨下=双色 LED）

**当前各位显示口径（位 0 = 最右，对应 top 的 seg_scan 例化）**：

| 位 | 显示内容 |
|---|---|
| 0 | 灭 |
| 1 | 灭 |
| 2 | **音量档**（仅音量模式调节后约 2 秒内显 0~F，超时或切模式立即灭） |
| 3 | **图片编号**（当前显示图 1~4） |
| 4 | **bank_valid**（上电流程 1→3→7→F） |
| 5 | **state_code**（状态码） |
| 6 | hang_dbg（带状条诊断位，正常灭） |
| 7 | 灭 |

### SPI Flash W25Q64（板载）

- FLASH_CS = P8
- FLASH_SDO = N8
- FLASH_SDI = P7
- FLASH_SCLK = M9
- FLASH_WP = P9
- FLASH_HOLD = R9
- 可用于参数持久化（任务 25）

## 4. 任务清单

### 第一批：小改动，不动核心架构

#### 任务 1：数码管扩展到 8 位 + 显示图片编号

**目标**：
- 当前最低位数码管显示读取图片的状态（state_code），**保留不动**
- 改为：在隔一位的那个数码管上显示当前图片编号
- 位置示意（从右往左数）：
  - `[0]` = state_code（状态码，保留原有，不动）
  - `[1]` = 全灭（中间空一位）
  - `[2]` = 当前图片编号（显示 1~4，对应内部编号 0~3）
  - `[7:3]` = 全灭
- 加载期间显示正在显示的图片编号（不是正在加载的）

**修改思路**：
1. 先把 `seg_scan.v` 从 6 位扩展到 8 位：
   - `seg_sel` 从 6 位改成 8 位
   - 新增 `seg_data_6`、`seg_data_7` 两路输入
   - `scan_sel` 计数从 0~5 改成 0~7
   - `SCAN_COUNT` 公式里的 6 改成 8
   - `seg_sel` 译码加 2 个 case
2. `sd_card_bmp.v` 已经有 `img_idx` 寄存器（当前显示的图片编号，2 位）
3. 顶层 `top_tf_hdmi_audio.v` 已经实例化了 `seg_decoder` 和 `seg_scan`
4. 当前 `seg_scan` 的连接：
   - 状态码接在原来的位置，不动
   - 其余大部分全灭
5. 改法：
   - 把 `img_idx` 传给顶层，加 1（`img_idx + 1` 变成 1~4），再经过一个 `seg_decoder` 译码后接到对应位置的 `seg_data`
   - 状态码原来接哪个还接哪个，**不要动**
   - 中间隔一位（空着）
6. `img_idx` 从 `sd_card_bmp` 的 `disp_buf_idx` 旁边引出，新增一个 output `img_idx_out`

**涉及文件**：
- `seg_scan.v`：从 6 位扩展到 8 位（新增 seg_data_6/7，seg_sel 8 位）
- `sd_card_bmp.v`：新增 output `img_idx_out`（2 位）
- `top_tf_hdmi_audio.v`：新增一个 `seg_decoder` 实例，把 `img_idx` 译码后接到对应位置的 seg_data
- `pin.adc`：补充 `seg_sel[6]`、`seg_sel[7]` 引脚约束（硬件已有 8 位，代码只用到 6 位）

**调试方案**：
1. 上板后看数码管：状态码还是在原来的位置
2. 隔一位的那位应该显示图片编号（1、2、3、4）
3. 按 KEY1 切图，图片编号应该跟着变（1→2→3→4→1...）
4. 自动轮播时数字也跟着变
5. 复位后数字回到 1

**验证标准**：
- 状态码显示位置不变
- 图片编号在隔一位的位置显示（1~4）
- 手动切图时跟着变
- 自动轮播时跟着变

#### 任务 2：轮播间隔改为固定 3 秒

**目标**：
- 当前自动轮播固定 1 秒（`auto_tick = (auto_cnt == CLK_FREQ_HZ - 1)`）
- 改为固定 3 秒，不做手动调节
- 3 秒足够图片加载完成，不会出现卡顿

**修改思路**：
1. `sd_card_bmp.v` 里的 `auto_tick` 当前是硬编码 1 秒
2. 把阈值从 `CLK_FREQ_HZ-1` 改成 `3*CLK_FREQ_HZ-1`
3. 时钟 100MHz，3 秒 = 300,000,000 个周期，阈值 = 299,999,999
4. `auto_cnt` 是 32 位，3 秒远没超范围
5. 不新增输入端口，不改顶层

**涉及文件**：
- `sd_card_bmp.v`：只改 `auto_tick` 那一行的阈值

**调试方案**：
1. 开自动轮播
2. 数秒表，确认两次切图间隔约 3 秒

**验证标准**：
- 自动轮播间隔约 3 秒
- 手动切图不受影响
- 加载忙时自动轮播暂停（已有逻辑：`!load_busy` 才计数）

#### 任务 4：数码管菜单系统

> 设计取向：先用拨码开关调参数，菜单系统后面有需要再做。

**目标**：
- 新增数码管菜单系统，通过 KEY3 短按/长按 + KEY1 调节所有参数
- 菜单参数：亮度(0)、对比度(1)、音量(2)、轮播间隔(3)、转场模式(4)
- 教程参考：`完赛系列/第十四讲/param_menu_controller.v`

**修改思路**：
1. 教程里的 `param_menu_controller.v` 已经实现了类似功能，参考它的状态机
2. 新增 `seg7_menu_controller.v` 模块：
   - 输入：key3_pulse（短按）、key3_long（长按）、key1_pulse
   - 输出：menu_mode（是否在菜单模式）、param_idx（当前参数号）、param_value（参数值）
3. 菜单状态机：
   - IDLE：正常播放，数码管显示图片编号
   - MENU：长按 KEY3 进入，显示参数号+值
   - 在 MENU 下，KEY3 短按切参数号，KEY1 加参数值
   - 长按 KEY3 或 5 秒无操作退出
4. 菜单模式下数码管：
   - `[6]` = param_idx（参数号）
   - `[5:3]` = param_value（参数值，3 位）
5. 参数输出送到对应模块：
   - param 0 → brightness（亮度）
   - param 1 → contrast（对比度）
   - param 2 → volume（音量）
   - param 3 → auto_period_sel（轮播间隔）
   - param 4 → transition_sel（转场模式）

**涉及文件**：
- 新增 `seg7_menu_controller.v`
- `top_tf_hdmi_audio.v`：实例化 + 连线 + 数码管多路选择
- 音频通路：加音量乘法器（配合音量参数）

**调试方案**：
1. 长按 KEY3，数码管应该进入菜单显示（显示参数号和值）
2. 短按 KEY3，参数号循环切换
3. 按 KEY1，当前参数值增加
4. 长按 KEY3 退出菜单，数码管恢复显示图片编号
5. 调亮度时画面亮度跟着变

**验证标准**：
- 菜单进入/退出正常
- 5 个参数都能调节
- 调节即时生效
- 5 秒无操作自动退出

### 第二批：按键交互增强

#### 任务 5：亮度/对比度按键复用 + 上一张/下一张方向切换

**背景（拨码重新分配）**：
- SW1 (C8)：原来对比度 bit0 → 改为"选调亮度还是对比度"（拨上/下决定 KEY3 调谁）
- SW2 (C7)：原来对比度 bit1 → 改为 sw_dir（切图/轮播方向选择）
- SW3 (C6)：恢复默认，**原样保留不动**（> 现状注记 2026/10/06：任务 18 起 C6 已改为 sw_key_mode 按键模式选择，"恢复默认"功能取消，以本文第 1 节硬件资源为准）
- SW4 (C5)：转场效果，**原样保留不动**
- 引脚约束 pin.adc 不改，C8/C7/C6/C5 还是那几个脚

**本任务分两步做，每步独立上板验证**：

##### 第一步：亮度/对比度按键复用

目标：原来对比度靠 SW1+SW2 两个拨码直读；现在改成 SW1 选调谁、KEY3 调档位。

修改思路：
1. 现在顶层：`contrast_level = {~sw_con1, ~sw_con0}`（拨码直读，2 位 4 档）
2. 把 `contrast_level` 从 wire 改成 reg [1:0]，删掉那行 assign
3. 原来 KEY3 always 块：按一下 `brightness_level +1`（2 位自动回绕）
4. 改成：按 KEY3 时看 SW1(sw_con0)：
   - sw_con0=0 → brightness_level +1

### 第五批：架构攻坚

#### 任务 20：FAT32 文件系统（方案 B 务实版）

**方案选型**：采用方案 B（务实版），不使用教程完整版（方案 A）。

- 教程文档低估了工作量：`bmp_read.v` 除读字节外还含完整多分辨率缩放管线（宽高比居中黑边、图小上采样含行缓冲、图大下采样抽点）。
- 方案 A（volume_scanner + file_streamer 全上、重写缩放）约 1200 行、风险高，暂不做。
- 方案 B 只用 volume_scanner 找簇号 → 转起始 LBA → 喂现有 bmp_read，缩放一行不动，约 150 行、风险低。

**方案 B 原理**：
1. 上电后 `fat32_volume_scanner` 解析 FAT32 引导扇区/BPB、读根目录，按文件名找 `PIC1.BMP`~`PIC4.BMP` 的起始簇号
2. 簇号转起始 LBA：`起始扇区 = data_start_lba + (簇号 - 2) × sectors_per_cluster`
3. 转换后的 LBA 锁存进 img_sector0~3，后续加载流程完全不变
4. scanner 与 bmp_read 共用一个 SD 扇区接口，用 scan_phase 仲裁（扫描时给 scanner，加载时给 bmp_read）；scanner 的脉冲 sector_req 用寄存器转成电平 sd_sec_read

**改动方案（6 处，均在 sd_card_bmp.v + 1 个新文件）**：
1. 新增信号声明：bmp_sec_*（bmp_read 独立扇区接口）、scn_sec_*（scanner 接口）、scn_*（扫描结果）、scan_phase/scn_read_lvl/scn_byte_cnt/scn_busy_reg（仲裁寄存器）
2. 新增仲裁 assign + 适配 always
3. 扫描结果：删除原 scan_found_valid 逐张缓存，改为 scn_scan_done 时一次性簇转 LBA 并算 img_found_count
4. 启动条件：`!scan_kicked && bmp_ready` 改为 `!scan_kicked && sd_init_done`
5. bmp_read 实例：scan_start 接 1'b0、scan_done/scan_found_* 悬空、sd_sec_* 改接 bmp_sec_*（经仲裁）
6. 新增 fat32_volume_scanner 实例（rst_n 接 ~rst）

**涉及文件**：
- 新增 `SD/fat32_volume_scanner.v`（从教程第七讲原样拷入，自包含约 407 行）
- 修改 `SD/sd_card_bmp.v`（上述 6 处）
- bmp_read.v、顶层 top_tf_hdmi_audio.v、pin.adc 均不改

**上板前操作**：
- TD 里 Add Source 把 fat32_volume_scanner.v 加入工程
- SD 卡 Windows 格式化成 FAT32，4 图改名 PIC1.BMP~PIC4.BMP 放根目录

**验证标准**：
- 上电正常显示 PIC1，按键切换/轮播、数码管编号、亮度对比度、SW2 方向均正常
- 互换 PIC1/PIC2 文件名后，显示顺序随文件名改变 → 证明按文件名识别
- 换图直接覆盖、不格式化即可显示新图

**方案 B 的已知边界**（本任务设计的固有限制）：

- **不支持碎片化文件**：方案 B 只取文件起始簇、转成起始 LBA 后让 bmp_read 连续读，**不跟踪 FAT 链**；若文件在卡上不连续（拷了又删、反复塞删文件），会读错/花屏。新格式化空卡拷 4 图必然连续，演示无影响。
- **不支持子目录**：只读根目录的 PIC1~4.BMP，图片放进子文件夹找不到。
- **不支持长文件名（LFN）**：只认 8.3 短文件名，名字必须是 PIC1.BMP 这种格式。
- **根目录只扫描第一个扇区（16 个目录项）**：4 图排在前面无影响；若前面塞十几个别的文件把图片挤出前 16 项，会漏图。
- **未移植 fat32_file_streamer（方案 A 完整版）**：以上限制的彻底解决都依赖它；需要时再上，做法是把 bmp_read 加载层换成 file_streamer 流式接口（含缩放对接，工作量大）。
