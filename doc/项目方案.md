## 1. 作品定位

**基于安路 EG4S20BG256 的店内音乐电子菜单**（对应赛题 1.1 场景：商业展陈终端 / 数字广告牌）。

- **每页一屏菜单**：一页两张商品卡片，各有商品图、中文名、一句短介绍与价格；
- **中文由 FPGA 叠加**：商品名/价格排版在图上，页面标题与介绍走 **PC 预渲染 mask**，FPGA 只做偏移读取 + alpha 混合 + 逐像素滑动；
- **可局部放大**：单键进入 2× 放大，看清商品细节，再按退出；
- 配套背景音乐（三首钢琴/拉格泰姆）+ 40 段频谱可视化，体现音画同步；
- 全部逻辑在 FPGA 内实现，无外处理器；链路：FAT32 扫描 → BMP 解析与缩放 → SDRAM 四 bank → HDMI 640×480@60；音频：RAW 流式 → HDMI 音频包 + DFT 频谱。

## 6. 构建与时序经验（踩过的坑）

- **`ext_mem_clk` 是画面正确性的命门**：帧缓存在 SDRAM，该域违例会产生横向乱纹。已知坏的构建是 −1.95ns；可用构建在 −0.03 ~ −0.6ns。
- 该域最差路径是**帧 FIFO 内部标志链**（读地址减法 → `rdusedw` 加法 → 比较，8 级逻辑含 6 级加法器），属 IP 结构，如需根治要把 `rdusedw` 流水化。
- 面积对布局极度敏感：同一网表不同种子，时序可差数 ns；95% 以上时容易"拿时序换可布性"。
- 种子选择判据（**2026-10-30 E19.21 起已不再靠抽奖**）：判据升级为 **所有域 `SWNS ≥ 0` 且 `HWNS ≥ 0`、违例端点合计 = 0**。达成路径：`sd_card` 100→75MHz、删死代码 `subtitle_render`、簇号→LBA 两级流水、流程内补跑 `fix_hold`（详见 `doc/archive/20261030/零违例攻坚记录.md`）。
- **hold 也要看**：TD 的 `fix_hold` 只在 `arr_filter == "on"` 时执行，默认流程 `arr_filter false` **从不修 hold**；本项目改为 `sim/DefaultFlow_hold.tcl`（`route` 后无条件插入 `fix_hold`）。手工 `import_db` + `fix_hold` 会让 TD 崩溃，必须走流程内插入。
- 综合黑盒陷阱：新模块未进 `.prj` 时 TD 只报 `HDL-7144/HDL-8007`，**exit code 仍为 0 并照样出 bit**，网表里却没有该模块（现象：面积/时序与上一版完全一样）。

5. **音乐快进 / 快退（±10 秒）** —— 2026/10/25 用户新增
   - **行为**：快进 10s；**超过末尾自动切到下一首的开头**；快退 10s；**退到 0 就停在 0**（不回上一首）；
   - **难点**：音频是从 TF 卡的 FAT32 簇链顺序流的，**没有反向链**。快进可以沿簇链跳过 960000 字节（48000Hz×10s×2B）；快退只能**从文件头重新走到目标位置**，或维护"每 10 秒一个簇号"的索引表；
   - **推荐实现**：播放时顺手记录 **每 10 秒的起始簇号**（一个曲目最多 60 项，存 BRAM/localparam 大小的数组），快进/快退直接跳到对应簇起点 → 两端都快、且无反向遍历；
   - **配套**：倒计时（右上角 `-MM:SS`）按跳转量同步跳变；频谱重新起跳；跳转期间保持画面不动；
   - **风险**：中高。seek 后音频 FIFO 需要**清空重灌**，否则会播到旧数据（爆音/错位）；快进到末尾切下一首要与现有 `track_player` 的结束逻辑对齐；
   - **验收**：连按快进 10 次能跨曲；连按快退到 0 后停住不再后退；跳转后声音与倒计时一致。

- **硬约束**：HDMI 输出固定 640×480（4:3），显示器自己拉伸到 1024×600（横向 ×1.6、纵向 ×1.25，横向多拉 1.28 倍）。因此 16:9 图片必然上下留黑边；2048×1200 也不会消除黑边（仍按 16:9 适配）。
- **做法**：图片改为 **4:3**，填满 640×480 画框；并按显示器做**横向预压缩 1/1.28**，使显示器拉伸后比例正确。压缩比做成脚本参数，换屏可调。
- 产出：`compose_menu.py` 增加 `--aspect 4:3 --squeeze 1.28` 两个参数，输出 1280×960（4:3）。

## 8. 演示注意事项

- **音量**：平时保持 0（静音），**演示前调到 15 档**——频谱标定与听感最佳点。
- **显示器是 1024×600**，系统输出固定 640×480：显示器若"铺满"会把 4:3 横向拉宽约 1.28 倍；**演示时切到 4:3 / 原始比例 / 点对点**。系统内部画的适配黑边与显示器黑边是两回事。
- **写卡后必须安全弹出**，直接拔卡会损坏 FAT32。
- **素材**：4 张 1280×720 菜单页 + 4 条 mask + 3 首曲目，全部在卡根目录，见 §3.1。
- **换图/换文案流程**：GPT 出"卡片版式 + 留白"底图 → 改 `compose_menu.py` 的 `PAGES` 重排中文 → 改 `make_subtitle_mask.py` 的 `CAPTIONS` 重生成 mask → 拷到卡。**换图后左上角分辨率表 `TAB_W*/TAB_H*` 也要同步改**。
- **固化**：现场演示前用 TD GUI 的 `PROGRAM_FLASH` 固化一次，之后上电即跑、无需下载器。

### 一、作品定位

### 二、频谱观感（本项目最长的一条调优链）

用户反馈顺序（每一轮都是一次上板实测）：

1. "起伏感不足" → 加平滑与峰值保持；
2. "太容易满音量" → 调整门限；
3. **"音量开到 1 都是几乎满量程，你确定标定正确吗"** → 查明是 AGC（帧最大值归一）吃掉了音量信息，**整套 AGC 删除**，改为固定参考（`msb≥8` 映射）；
4. "每四档一致，没做 16 档步进" → 排查证明**不是位宽截断**（iverilog + ModelSim 双工具确认 `vol*vol` 无 4 位截断），真因是平方律高档位每档仅 1.2 dB、**低于人耳可辨阈值**；
5. 改为 **16 档等 2 dB 步进**查表（0/349/440/554/697/878/1105/1391/1751/2204/2775/3493/4398/5537/6970/8775）；
6. 用户：**"现在这个效果我满意了"**（作为该线索的收尾）。

沉淀的经验：**1.2 dB/档不可闻，2 dB 才可辨**；频谱标定基准为满档材料（约 −1 dBFS）。

### 三、素材与场景

- 四张海报由用户用 ChatGPT 生成，助手提供提示词；**原生尺寸由转换脚本决定**（GPT 只按自己的尺寸出图）。
- 四张按"缩放适配演示矩阵"输出：640×480（原生满屏）/ 800×600（4:3 缩小满屏）/ 480×640（竖版放大，左右黑边）/ 1280×720（16:9 缩小，上下黑边）。
- 曲目：Airport Lounge、Bossa Antigua、The Jazz Piano（免版税），要求"能同时听到贝斯和镲/沙锤"，使 40 根柱子从低到高都填满；峰值统一到 −1.0 dBFS 附近。
- 字幕文案原则：**每条 ≤32 字符**，正好一整行显示完（窗口 256 列 ÷ 8 = 32 字符）。

### 六、工具链经验

- **烧录**：`D:\TD5.6.2\bin\bw_commands_prompt.exe`（BitWriter 命令行）+ `download -bit ... -mode jtag -spd 7 -cable 0`；路径必须正斜杠。`bw.exe` 是 GUI。
- **综合/布线**：`td_commands_prompt.exe DefaultFlow.tcl`；种子在 `Runs/phy_1/settings.cfg` 的 `place seed N`。
- **仿真**：ModelSim SE-64 10.1c；ROM 用 `ifdef ..._SIM` 走 `$readmemh`，综合走 `EG_LOGIC_BRAM` + `.mif`。
- **图像转换**：`src/user_source/hdl_source/python/png_to_bmp.py`（按矩阵输出四种原生尺寸）、官方 `doc/TF卡/convert/`（含 `sync_to_sd_safe.py`：意识到 FPGA 是裸扇区扫描，普通删除无效）。
- **音频转换**：`mp3_to_track_raw.py`（48k/16bit/单声道 + 峰值归一；注意 volumedetect 与裸 PCM 峰值差约 0.8 dB）。
- **辅助脚本**：`sim/seed_sweep.ps1`（自动扫种子）、`sim/burn_jtag.tcl`（烧录）。
- **PowerShell 陷阱**：无 BOM 的 UTF-8 脚本被 5.1 按 ANSI 读 → 中文把语法搞坏；不要用 `Get-Content | Set-Content` 批量改中文文档（曾造成乱码）。改用写入工具。

### 七、2026/10/25 定位调整：电子菜单 + mask 字幕 + 局部放大

- **定位**：从"离线数字海报屏"改为**店内音乐电子菜单**。理由：赛题场景里"商业展陈终端"更贴近真实用途，且"一页两商品 + 价格"能把 OSD、字幕、缩放、放大四条加分项串成一条完整叙事。
- **字幕方案**：放弃"FPGA 内 5×7 点阵拼字"，改为 **PC 预渲染 512×32 / 2bit mask**。判据是"汉字 + 品牌字体 + 抗锯齿"三样点阵都做不到；且 mask 顺带把滑动变成逐像素。
- **为什么不用"图像里画字"**：商品名/价格确实排在图里（`compose_menu.py`），但**页面标题**仍走 FPGA mask——既保证画面精致，又保留"FPGA 叠加中文"这条加分证据。
- **为什么选 2bit 而不是 1bit**：用户要求"像素感弱"，1bit 边缘锯齿明显。代价是 BRAM 翻倍（16KB），但 BRAM32K 基本空闲，不占 LUT。
- **为什么砍掉 TF 卡参数持久化**：占面积、非加分点，收益远低于成本。
- **为什么测试音要"朴素频谱"**：用户判断"关掉强调峰、只反映振幅"更能体现音画同步；强调扫过是"为了好看"，反而干扰证据。
- **为什么曲目换快的**：拉格泰姆音符密度高，40 段柱子同时有事干；慢曲子柱子矮而稳，看不出音画同步。

### 八、2026/10/26 缩放适配口径（用户决定：不为该加分项加素材）

- **背景**：加分③要求"任意源尺寸等比适配 + 居中黑边"。四张菜单图现统一 **1280×960**，现场切页恒为满屏，**黑边看不出来**。
- **曾评估**：把第 4 页换成 16:9 活动海报，用黑边体现适配。**否决**，原因两条：①会挤掉第 4 页的两个商品，菜单完整性受损；②更关键的硬约束——**显示几何（宽/高/偏移）现在是全局一份**（E19.0 资源清理删掉了每 bank 的那份），混尺寸素材会导致"切到海报再切回菜单页时用海报几何显示"，必须先把几何表补回来才能安全混尺寸。
- **最终口径**（用户 2026/10/26 决定）：**不为这条加分项新增素材或改几何架构**。现有实现已覆盖缩放能力的两端，演示时口头说明即可：
  - **下采样适配**：源 1280×960（大于 640×480 输出）等比缩放到满屏，无变形无裁切；
  - **上采样放大**：局部放大 2× 双线性，320×240 → 640×480；
  - 代码本身接受任意 16 位尺寸的 24bit 无压缩 BMP（`bmp_read.v` 头部校验 + 小数步进最近邻），只是"混尺寸同卡"需要几何表才安全。
- **连带记录**：若将来要恢复"混尺寸演示"，最小代价是加一张 **4 项几何常量表**（bank0~2 = 640×480 满屏、bank3 = 按海报比例），约 20 LUT，无需触发器。
